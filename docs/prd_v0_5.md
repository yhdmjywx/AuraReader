## 1. 产品定位与目标读者

### 1.1 产品定位

**以阅读者为主体的阅读工作台。AuraReader 让读者按照自己的意图开展和组织阅读。**

读者自己的目的可以联系起不同书籍、或同一本书不同位置的内容，也可以在阅读过程中继续变化。AuraReader 让读者能够围绕自己的目的阅读、查看和编辑相关内容，使阅读活动的组织能够跨越单本书籍与单一页面。

### 1.2 目标读者

**希望按自己的意图开展阅读的人，不以职业、阅读深度或用途区分。**

产品不预先规定哪些阅读目的值得支持，也不要求读者证明目的具有学习、研究、工作或产出价值。目的的含义由读者自己决定；是否明确表达目的、是否使用 Goal，也由读者决定。

### 1.3 阅读者主体性贯穿整个阅读服务

沉浸式高亮、页边笔记与核心的 Goal 系统共同支持以阅读者为主体的阅读服务。产品围绕读者自主开展阅读的过程组织这些能力，使读者自己的关注、表达与目的能够在阅读中持续发展。

沉浸式高亮与页边笔记让读者自主选择关注什么，在原文旁记录和编辑自己的想法，使阅读、表达与继续思考保持连贯。它们在阅读当下为读者的主体地位提供支持。

Goal 承载读者自主定义、持续发展的阅读目的，并与高亮、页边笔记及书籍联系起来，让读者看到来自不同书籍、或同一本书不同位置的、与同一个阅读目的有关的内容。读者可以沿着自己的目的查看相关材料，也可以回到原文继续阅读，使当下的阅读与围绕目的组织内容相互联系。

是否表达目的、建立 Goal 或关联某次批注，都由读者决定。未设置 Goal 或未建立关联时，沉浸式高亮与页边笔记仍在同一阅读服务中支持读者自主阅读和思考。

### 1.4 Goal 的产品原则

1. **目的由读者定义**：不预设目的类别、发展方向或最终产出，不要求目的必须可量化、有期限或能够判定完成。
2. **独立于书籍存在**：Goal 可以先于书籍建立，也可以在阅读中产生；没有书籍、高亮或笔记时仍能存在。同一阅读目的可以关联多本书中的内容，同一本书也可以与多个 Goal 有关。
3. **随读者的意图发展**：Goal 可以改写、展开为子 Goal，也可以终止或删除；子 Goal 的含义与发展由读者决定。
4. **关联由读者建立**：由读者决定哪些材料与自己的目的有关；材料的位置或主题不替读者决定这种关系。
5. **核心但可选**：Goal 的核心地位服务于读者自主性。读者可以完全不设置 Goal，仍能自由阅读、高亮和记笔记。

本节描述产品定位与原则。现有源码已支持独立 Goal、自由文字编辑、子 Goal、跨书材料关联与不设置 Goal 的阅读，也支持完成／重新开启、归档／恢复、最近删除及逐条恢复或永久删除。最近删除的批量清空尚未实现；本轮生命周期实现未制作或验证新版安装包。具体范围见 [书籍模块实现记录](goal-books-implementation.md) 和 [生命周期验证](goal-lifecycle-verification-2026-10-27.md)。

### 1.5 当前交付形态

当前面向 PC，提供 Windows x64 Electron 桌面候选版，并保留 Node.js 本地服务与浏览器模式；已支持的阅读格式为 EPUB、TXT。运行平台与文件格式说明当前交付范围，不限定读者的职业、阅读深度或用途。安装包未签名、尚未公开发布；最新源码能力与候选包验证范围分开记录。安装见 [开发文档](development.md)，存储与迁移见 [数据与备份](data-and-backup.md)，导出见 [阅读指南](reading-guide.md)，具体限制见 [已知限制](known-limitations.md)。

产品动画应串起 Goal 建立、关联书籍、在不同书中批注、主动归入材料、回看与改写目的的完整过程。以目的如何随阅读发展为主线，不将首页变为操作手册，也不暗示系统自动理解意图或自动关联材料。Goal 可以有不同后续方向，不以可量化完成或某种产出定义阅读价值。

## 2. 输入是什么？ (Inputs)

### 2.1 文件与内容输入

- **本地电子书文件**：
  - `.epub`：解析 EPUB 2/3 包中的元数据、章节 HTML 与目录，处理书内链接及图片等资源。不以某本书固定的目录数量作为格式规范。
  - `.txt`：导入文本并生成可阅读内容。
  - 系统内置示例书籍，可从书库的“示例图书”入口切换。
  - 文件选择器虽包含 `.pdf`，但尚未实现 PDF 正文解析；不将其列为正式支持的输入格式，也不把 `.equb` 或任意 `.zip` 当作已支持入口。
- **本地迁移备份文件**：
  - `.aurabackup`：每文件包含一本书的解析后正文、目录及可选高亮、笔记，不含全局设置和自定义字体；兼容已有多书备份及符合既有备份结构的 `.json` 文件，非任意 JSON。
- **字体文件**：在“更多字体”内导入 TTF、OTF、WOFF2，或读取、搜索 PC 已安装字体。

### 2.2 用户交互与配置输入

- **文本划选与标注交互**：
  - **选中文本**：支持跨段落、内联标签及多行选区，通过精简浮动工具条添加高亮或笔记。
  - **高亮**：正文显示黄色背景；已有高亮可删除，不强制创建笔记。
  - **添加笔记**：选文后点击“记笔记”，直接在对应页边位置进入编辑，自动获得输入焦点并显示红色原生光标，无弹窗、二次聚焦或保存按钮。
  - **继续编辑**：点击已有笔记原位输入，多行内容随输入扩展高度；`Enter`、`Shift+Enter` 正常换行，IME 组合输入不误触完成操作。
  - **退出编辑**：`Esc`、`Ctrl+Enter` 或点击外部结束编辑，保留已有输入；输入过程自动保存，退出编辑不等于触发一次需要确认的保存。
  - **空白处理**：新建但未输入的笔记退出后不保留；已有笔记清空后退出则删除该笔记及对应下划线，独立高亮不受影响。
  - **删除**：已有标注气泡按类型提供删除高亮、删除笔记；页边笔记亦保留删除入口。重叠标注分别处理。
  - **原文关联**：新笔记必须引用正文，不提供独立随笔输入框；旧独立随笔继续保留在存储、备份及相应导出中。
- **阅读布局与视口交互**：
  - **模式切换**：外观面板选择阅读版式，`D` 切换单页／双页；另支持连续滚动阅读。
  - **翻页**：底部上一页／下一页及 `←` / `→`；双页按一组两页／栏推进，末尾边界不得溢出。滚动模式以连续正文阅读。
  - **页边笔记**：无需展开或收起，跟随当前可见正文；单页或双页、翻页或滚动均更新可见笔记，跨页引用只要有交集就显示。
  - **全屏阅读**：顶部按钮进入／退出浏览器全屏。
  - **顶部功能区**：书库、外观、导出与备份、全屏依次排列。前三个为互斥浮动面板，支持再次点击入口、点击外部或 `Escape` 关闭。
  - **书库**：紧凑列表条目打开书籍，次级按钮删除；顶部保留“导入书籍”“示例图书”。
  - **目录导航**：书名旁入口打开目录抽屉，按实际章节层级和锚点跳转。
- **阅读偏好与排版定制**：
  - **首行缩进**：无缩进、2 字、3 字，切换后即时应用。
  - **字体选择**：默认“自动选择”，简体中文使用更纱黑体，英文使用 Literata；其他或未知语言使用系统回退。亦可手选内置字体、本机字体或已导入字体。
  - **更多字体**：在现有字体菜单内切换浏览视图，支持搜索、本机字体、文件导入和再次选择，顶部可返回；不新增设置行或独立管理页。
  - **字体回退**：Literata 缺失的中文字符由更纱黑体等回退处理；保留粗体、斜体表达。全局字体偏好即时生效并持久化，不提供逐书字体配置。“原书字体”暂不启用。
  - **其他设置**：字号、白色／护眼／夜间阅读背景、界面明暗，沿用现有设置面板。
- **备份与迁移交互**：
  - 从导出面板进入选择性书籍备份：多书复选、全选／取消全选、选择是否包含标注；每本书分别生成文件，不保存全局设置。
  - 从备份恢复到本地 SQLite；不因当前屏幕笔记筛选而遗漏全书标注。
- **快捷键安全互锁规则**：输入框、文本域、原位编辑、输入法组合输入和相关面板／对话框操作期间，不让全局阅读快捷键干扰当前操作。废弃的侧栏快捷键 `B` 不再作为产品功能。

### 2.3 Goal 与 Library 的当前规则

本节补充 Library 首页与 Goal 的规范。阅读中的紧凑书库 Popover、原位笔记、阅读排版、导出面板及键盘互锁规范继续保留；Library 首页不替代阅读工具栏的书库面板。原笔记侧栏的废弃不代表移除当前 Goal 侧栏。

- **自由开始**：首次空库可建立 Goal 或直接导入 EPUB／TXT；根层级可打开全部书籍，不必先定义目的。左上角 AuraReader 标识进入 Library，有当前书籍时可继续阅读。
- **书籍组织**：Library 根层级显示顶层 Goal 和全部书籍，进入 Goal 后显示直接子 Goal 及主动关联的书籍；同书可关联多个 Goal，子 Goal 不复制父级书单，移除关联保留原书。浏览或创建不改变当前阅读意图，从 Goal 开书才切换意图，从根层级开书不偷偷沿用旧 Goal。
- **Goal 导航**：Home 回根层级，上箭头返回上级，路径逐层导航；唯一的＋在当前层级创建并留在原处，点击条目才进入。Goal 文字可原位编辑，不预设分类。切书／换章节不隐藏直接子 Goal，切书保留当前 Goal 与材料展开状态。
- **阅读侧栏与材料**：单页左侧 Goal 侧栏宽 220–640px，支持拖拽、方向键、Home／End、双击复位和偏好保存；放大进入独立 Goal 页面，收起回到原阅读位置。高亮浮条和笔记原操作区的 Goal 按钮由读者主动关联材料，归入或重新进入后展开摘录。跨书材料显示书名，点击回到原文；`×` 只解除关联。不恢复顶部 Goals 按钮或 All goals／Current goal 切换。
- **生命周期**：父 Goal 完成向下覆盖全部后代，子 Goal 完成不改变父级，重新开启只作用于自身；完成与归档独立。归档分支及恢复保留层级，删除进入最近删除，可按原路径（含必要祖先）或根层级恢复，也可永久删除分支。永久删除只清除 Goal 与关联，不删除书籍、高亮或笔记；归档／删除当前意图保留当前书籍及位置，恢复不自动选择意图。菜单、确认框与筛选操作不得触发正文翻页。

当前实现与验收边界见 [书籍模块](goal-books-implementation.md)、[跨书实现](goal-cross-book-implementation.md) 和 [生命周期记录](goal-lifecycle-verification-2026-10-27.md)。

## 3. 输出是什么？ (Outputs)

### 3.1 界面交互输出

- **正文与沉浸式页边笔记工作台**：
  - **单页视图**：正文通常按 560px 阅读宽度排列，笔记位于外侧；空间不足时按现有布局计算处理。
  - **双页视图**：两栏正文各 560px、栏间距 72px，总宽 1192px；外围留白随窗口变化，不以固定左右 210px 作为所有窗口的要求。
  - **连续滚动**：保留连续正文、标注、笔记及导航行为。
  - **简洁阅读背景**：正文与笔记共享阅读背景，无大型圆角纸张容器、书脊阴影、侧栏分界线、笔记卡片边框或召回把手。
  - **空间变化**：笔记按可用空间排列在两侧、右侧或底部，不压缩双页每行宽度。阅读可用宽度小于 1224px 时，双页临时降为单页；空间恢复后恢复双页，不覆盖用户偏好。
  - **位置与选区关联**：切换模式或排版时保留当前阅读定位；右页选区与章节流的真实范围关联，不错误归到左页，不跨书串线。
- **页边笔记展示**：
  - 直接展示笔记内容，不重复显示引文、章节徽章、时间或“随笔思考”等装饰；原文引用和选区关联仍保存在数据及导出中。
  - 高亮呈黄色背景，笔记关联文本呈红色下划线，可同时存在。
  - 只显示与屏幕正文相交的笔记，编辑时保留当前编辑器稳定，不因自动保存而重置焦点、光标或 IME。
  - 保留全书笔记的内部查询／范围接口，但不新增前端全书查看入口；全书导出和备份始终使用完整数据。
- **浮动面板、抽屉与弹窗**：
  - **统一面板容器**：书库、外观、导出面板宽 300px，距右侧 16px，位于工具栏下方 8px；复用背景、圆角、边框、阴影和内边距。极窄窗口仍受现有视口宽度限制。
  - **本地书库 Popover**：纵向紧凑列表展示书名、格式、章节数，条目打开阅读、次级按钮删除；长标题省略并保留完整标题提示。空书库给出导入提示，书多时内部滚动；本地保存及备份提醒降低视觉权重，无大面积遮罩。
  - **外观与导出面板**：保留既有内部 UI 与功能。统一容器不触发临时切换单页或改变正文宽度；1920px 宽屏双页可置于右侧留白，较窄双页面板仍可能遮挡正文，本轮未实现额外避让。
  - **书籍目录抽屉**：展示书籍实际目录层级，供章节与锚点导航。
  - **选择性多书备份弹窗**：保留多书选择及是否包含标注，不提供“包含应用设置”选项；笔记编辑不使用此类弹窗。
  - **Toast 轻量通知**：提供操作结果和错误反馈，失败时不能误报已持久化。

### 3.2 导出的文件产物

需要在 AuraReader 恢复使用时选 `.aurabackup`；需要 Markdown、知识库或 AI 输入时选“按章节导出”；摘要 Markdown 为补充。HTML 导出已废弃。

1. **按章节导出（`.md`／文件夹）**：
   - 单章直接保存为 Markdown。多章选择保存位置后新建“书名_章节导出”文件夹，内含 `00_目录概览.md` 和按原编号命名的 Markdown 文件；同名目录自动加序号。
   - 高亮直接嵌入正文为 `<mark>原文</mark>`，跨段高亮分别闭合，不另列纯高亮卡片或重复整段正文。
   - 笔记置于对应原文段落之后，以引用块呈现“原文引用”、准确选中文字和笔记内容，不统一堆到章末，不加“随笔思考”标签。
   - 笔记有意引用选文，不适用旧规范“绝对零原文重复”。重复引用按原有选区关联定位；无法定位的历史笔记保留兜底输出，不静默丢弃。
   - 可在支持相关 HTML 标记的 Markdown 编辑器（如 Obsidian、VS Code 预览）使用；不承诺所有平台的 Markdown 方言均保留高亮。
   - 统一使用顶栏“按章节导出”入口，点击后原位替换为“当前章节／全部章节／选择章节”，以约 200ms 的高度变化和淡入衔接。当前和全部章节直接打开系统保存选择器；自选时才展开章节复选列表与取消／导出按钮，无选择时禁用导出。不显示高亮／笔记统计，不弹出遮罩，不锁定阅读正文；系统减少动画设置下停用转场。
   - 当前章节按点击导出时的阅读位置确定。按现有阅读内容单元选择，同一源文件内的多个目录锚点一并导出，纯卷标题随对应首章保留。切换书籍后清除旧书自选状态。
   - 部分导出仅包含所选内容的正文与标注、相关目录和原章节编号；整书导出保留未归属笔记兜底文件，整书仅一个内容单元时追加到该章 Markdown。取消或失败不报告成功，自选状态保留供重试；文件夹失败清理本次创建的内容。
   - 网页版多章导出使用浏览器目录授权接口，不支持时提示使用桌面版；不自动回退 ZIP。
2. **笔记摘要（`.md`）**：汇编全书标注引用及笔记内容，不包含全书正文，适合只需摘要的用户；不是独立 JSON 导出。
3. **逐书备份（`.aurabackup`）**：JSON 结构的专用备份，每文件一本书，含解析后正文、目录及可选标注；多书分别下载，可在 AuraReader 恢复到 SQLite。不是原始 EPUB 的逐字节副本，不含全局设置和自定义字体，建议另存原始 EPUB。

## 4. 什么情况下算是成功？ (Success Criteria / Definition of Done)

- **解析与跳转准确性**：测试 EPUB 的目录、正文顺序、章节和锚点映射一致；图片与内部链接在已支持样本中正常工作。复杂 EPUB 的兼容问题应明确记录，不以“所有 EPUB 100% 成功”代替测试。
- **布局与定位**：单页、双页、滚动均可阅读；双页固定行宽和栏间距不受笔记挤压；宽度不足降级、恢复及模式切换不破坏当前位置；不再出现废弃侧栏控制。
- **沉浸式笔记**：默认按可见正文交集展示，离开页面后不残留无关笔记；创建立即可输入，无弹窗、无手动保存，连续输入、IME、多行与退出行为正常。
- **标注独立性**：黄色高亮与红色笔记下划线独立创建、删除和重叠；编辑同一笔记保持原记录，不因类型或色彩自动转换而增删其他记录。
- **导出质量**：单章 Markdown、多章文件夹、摘要和备份正常保存；跨段 `<mark>` 闭合、正文完整、笔记引用准确且位于对应段落后；目录链接指向已导出文件；屏幕筛选不限制全书导出。
- **本地持久化与恢复**：书籍、标注经 SQLite 确认写入后，刷新和服务重启仍可从书库重新打开；保存失败保留待写操作并提示，旧请求不能覆盖新版本或复活删除记录；书籍与关联标注一起删除。
- **迁移安全**：迁移前归档原始 IndexedDB、缓存及待写操作；验证数量、ID、完整对象、内容及关联后切换；冲突停止切换并保留证据，不清空原 IndexedDB，不长期双写。
- **界面一致性**：书库、外观、导出面板宽度与右侧位置统一，打开互斥，外部点击、Escape 与再次点击关闭；不增加窄窗临时切单页逻辑。
- **质量与工程保障**：`npm test`（语法、单元和回归）通过，数量以实际测试目录为准。涉及 SQLite 的验证使用真实数据库文件；浏览器交互与真实用户数据迁移范围分别报告。
- **产品入口一致性**：README 首要展示 Goal 且明确完全可选；演示、PRD、使用文档的能力与边界一致，媒体及迁移后的文档链接可解析，不把历史验收结果算作本次验证。

## 5. 哪些内容不能生成？要保存哪些记录？支持哪些格式？

### 5.1 哪些内容不能生成？ (Prohibited Output)

- 不将纯高亮额外拆成重复正文列表；笔记保留必要原文引用，不以“去重”为由删除其语境。
- 不生成跨段未闭合 `<mark>`、损坏 HTML、错误选区或跨书关联；不能只靠引用文字相同就把笔记安到错误段落。
- 不因自动保存、退出编辑、删除及迟到请求而丢失内容、复活标注或误报成功。
- 不在迁移冲突时静默覆盖、删除未知字段或重解析 EPUB 替代原书籍数据；不以清空 IndexedDB 绕过迁移。
- 不自动上传书籍与笔记到云同步或 AI 服务；但不将此写成零外部资源请求，现有 CDN 依赖必须如实说明。
- 不再创建无原文引用的独立随笔，不新增手动保存按钮、笔记编辑弹窗或废弃侧栏兼容层。

### 5.2 要保存哪些记录？ (Persistence Records)

以下端口、项目 `data/` 路径及 IndexedDB 迁移适用于本地服务／浏览器模式。Electron 通过 IPC 访问独立 SQLite 书库，数据位于 `%APPDATA%\AuraReader\data`，不自动导入旧浏览器数据；详见 [开发文档](development.md) 与 [数据边界](data-and-backup.md)。

- **SQLite 主数据库**：`data/aurareader.sqlite`，由 Node.js 内置 `node:sqlite` 管理，要求 Node.js >= 24.15.0；本地 API 统一读写，默认端口 8095、只监听 `127.0.0.1`。
  - `books`：保存完整书籍 JSON，包括 ID、标题、格式、解析后的章节 HTML（`pages`）、目录（`toc`）、语言等字段；保留未知及历史字段。另存版本、书籍代际与删除状态。
  - `annotations`：通过 `book_id` 关联书籍，完整保存标注 JSON，包括 ID、类型 `kind`、引用 `quote`、笔记 `comment`、页码、章节、选区位置与偏移等；保留未知字段。另存版本与删除状态。
  - `operations`：记录操作 ID、请求哈希及结果，用于提交成功但响应丢失后的安全重试；版本和删除记录防止旧请求覆盖或复活记录。
  - `migrations`：记录来源、快照及校验清单，支持迁移重复执行的识别。
  - `goal_library`：保存全局 Goal JSON、层级、材料关联、主动书籍关联及生命周期状态，并保留 revision、幂等和事务约束；不是每书独立复制一份 Goal。SQLite v4 的已有迁移、每书备份图与删除清理规则见 [跨书实现](goal-cross-book-implementation.md)、[书籍模块](goal-books-implementation.md) 和 [生命周期验证](goal-lifecycle-verification-2026-10-27.md)。无书籍来源或关联的独立 Goal 需由 SQLite 一致性备份覆盖。
  - 日常业务不再使用 IndexedDB；浏览器仅在一次性迁移流程中只读旧 `AuraReaderDB`，不得自动删除原数据。
- **localStorage 客户端偏好与短期恢复**：
  - 保留阅读模式（`aura_layout_mode`：`single` / `double` / `scroll`）、缩进、阅读背景、界面明暗等现有偏好。
  - 字体偏好（`aura_font_preference`）、搜索内容（`aura_font_search`）及最近选用本机字体（`aura_font_recent_system`）继续按浏览器访问地址保存。
  - `aura_notes_pending_{bookId}` 仅保留尚未确认的保存／删除操作，确认成功后清理；不恢复整书长期笔记缓存，不形成第二套主数据库。
  - 废弃侧栏比例和折叠配置不再读取、应用；无需主动删除用户历史键。
- **字体及迁移归档**：导入字体保存在 `data/fonts/`；原始迁移快照保存在 `data/migration-snapshots/<来源哈希>/<快照哈希>/`，冲突报告保留 `conflicts.json`；`data/` 不纳入 Git。
- **校验、备份与恢复**：
  - `node src/server/storageMaintenance.js verify` 校验数据库；`backup` 在 `data/backups/` 生成一致性 SQLite 备份。
  - 保留 `storage-installed.json`；已建库的数据库丢失或为空时停止启动，避免静默生成空书库。复制运行中的主文件不能替代一致性备份，须考虑 WAL。
  - 换机或替换项目目录前导出逐书备份，或完成 SQLite 一致性备份并保留整个 `data/`；恢复前停止服务、保留原数据副本并在隔离目录验证。
  - 不同浏览器或端口连接同一服务时共享项目书库，偏好按地址隔离；首次旧数据迁移必须在原浏览器、配置文件及访问地址进行。
  - 原始数据、普通缓存、待保存和待删除操作按现有恢复规则合成；普通旧缓存不覆盖较新数据库记录。无法判定的同 ID 冲突、仅缓存记录或孤立标注阻止相关来源切换；单次迁移上传上限 256MB，超过则停止而非截断。

### 5.3 支持哪些格式？ (Supported Formats)

- **输入支持**：电子书 `.epub`、`.txt`；专用备份 `.aurabackup` 与符合旧备份结构的 `.json`；自定义字体 `.ttf`、`.otf`、`.woff2`。PDF 正文解析未实现。
- **导出支持**：单章 Markdown、多章 Markdown 文件夹、笔记摘要 Markdown、逐书 `.aurabackup`；HTML 已废弃，不提供章节 ZIP 或独立标注 JSON 的当前菜单入口。历史阶段的 HTML／ZIP 验收记录继续保留。
- **字体分发**：仅更纱黑体与 Literata 为内置正文精选字体，离线可由本地服务加载；开源许可随字体资源分发，导入字体不复制进公开源码。
- **许可证**：项目代码 Apache-2.0，字体与第三方依赖遵循各自许可；Project Gutenberg 测试 EPUB 保留书内声明，不纳入项目代码许可证范围。

## 6. 要做什么，不做什么？ (In Scope vs Out of Scope)

### 6.1 要做 (In Scope)

- 面向 PC 的本地 EPUB / TXT 阅读工作台，提供 Windows x64 Electron 候选版及本地服务／浏览器模式；源码模式先安装依赖，`npm start` 或 `npm run desktop` 自动检查类型并构建。
- 目录层级与锚点导航、内部链接及图片处理，单页／固定双页／连续滚动、全屏、键盘互锁和阅读设置。
- 跟随当前可见原文的沉浸式页边笔记，独立高亮与笔记、跨段／重叠选区、原位自动保存和必要删除入口。
- 两款内置字体、按语言自动选择、本机字体、字体文件导入及全局偏好，不增加独立字体管理页。
- Library 按 Goal 浏览书籍、直接导入与打开书籍；Goal 独立、跨书、可选，保留阅读侧栏与独立页面，按 2.3 执行。阅读中的紧凑书库 Popover 及与外观、导出面板的容器规范继续保留。
- 按章节 Markdown（单章文件／多章文件夹）、笔记摘要及逐书 `.aurabackup`；书籍、高亮和笔记整合迁移。
- SQLite 作为唯一主要持久化数据库，短期待写恢复、原始快照归档、迁移冲突保护、一致性校验与备份。
- 使用真实模块、API 和 SQLite 的测试；DOM 与浏览器交互按实际需要验证，不保留只为旧断言存在的空实现。

### 6.2 不要做 (Out of Scope)

- 手机竖屏、竖长或其他异形视口的完整适配；现有桌面宽度变化不等于承诺移动端支持。
- 本轮工具栏面板的窄窗正文避让、打开面板临时切单页或改动内部功能 UI。
- 云端账户、中心化同步、多人协作、社交评论及应用内 AI 自动总结；用户可自行使用导出文件。
- 独立随笔写作、手写涂鸦、复杂笔记编辑工具栏及笔记模态编辑器。
- 旧笔记侧栏拖动、展开／收起、召回把手及相关快捷键的恢复；当前 Goal 侧栏按 2.3 保留。
- 原书字体完整恢复、复杂 EPUB 样式完全保真、PDF 正文解析、逐书字体配置或字体商店。
- 长期保留 IndexedDB／SQLite 双写、自动清空用户旧库或将 localStorage 当作第二套主数据库。
- 承诺浏览器模式完整离线启动：该模式界面图标、界面字体及 JSZip 仍依赖外部 CDN；桌面资源随包提供，其离线验证范围以阶段记录为准。本机字体可用性还受环境和授权影响。
- 将“数据仍在”解释为“刷新后自动恢复上本书及原位置”：当前重载不会自动恢复上次打开的书籍和阅读位置，需从书库重新打开。
