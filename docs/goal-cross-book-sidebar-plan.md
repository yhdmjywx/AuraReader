# Goal 下一阶段实施计划：跨书延续与独立 Goal 页面

日期：2026-10-26。代码基线：`89defc4`（`feat(goals): add resizable sidebar presentation`）。本计划已实施；变更与验收结果见 [跨书 Goal 实现记录](goal-cross-book-implementation.md)。下文保留获批的实施边界与验收要求。

依据本轮确认：切换书籍后的 Goal 继续采用 Sidebar 方案；Goal 页面不再重复显示左侧 Goal 侧栏。沿用此前原则：Goal 归属于读者，保留树和既有材料交互，复用当前代码与 UI；其他功能行为保持不变。

## 1. 当前 UI/UX 与代码检查

| 当前情况 | 影响 | 下一阶段处理 |
| --- | --- | --- |
| `GoalController.setStateForBook()` 随书安装状态、重新选择根节点并重置展开；`AppCoordinator.openBook()` 每次调用 `loadGoalsForBook()` | 切书仍相当于换一套 Goal，Sidebar 外观没有解除归属限制 | 书籍会话与当前 Goal 分开；切书仅更新阅读来源上下文 |
| 顶部 `Goals` 实际只控制侧栏收放；产品尚无独立 Goal 页面 | 用户无法离开书籍继续处理 Goal，导航入口与显示开关含义混在一起 | `Goals` 进入独立页面；阅读侧栏用单独图标收放 |
| `All goals` 渲染的仍是当前书内节点 | 文案与全局 Goal 的预期不符 | 全局树覆盖全部 Goal；不按书复制树 |
| `GoalUI` 只从当前书的 annotations 集合寻找材料，并把未找到的关联过滤掉 | 跨书后其他来源材料和计数会消失 | Goal 单独读取已关联来源，形成材料视图；原阅读 annotations 集合保持书内范围 |
| `jumpToAnnotation(id)` 只在当前书的笔记／高亮中查询 | 不能从 Goal 打开其他书的材料 | 先按明确来源切书，再走原定位方法 |
| 当前只有一个 Goal 渲染器；体验稿的 Goal 页面曾同时保留左侧树和主区 Goal | 直接复制体验稿会出现重复 Goal 内容和多套入口 | Goal 页面隐藏侧栏与分隔条，只在主区挂载同一个 Goal 渲染器 |
| `ResizeObserver` 在工作区宽度变化时触发原有 refit，Sidebar 在非单页或窄窗中隐藏 | 将阅读区隐藏以进入 Goal 页面，会产生宽度 0 的回调；独立 Goal 页面也可能被阅读模式误隐藏 | 页面状态先于布局判断；隐藏阅读区不 refit，Goal 页面不受阅读模式及 940px 阈值控制 |

主要检查位置：`features/goals/goalController.ts`、`goalUI.ts`、`goalLayout.ts`，`app/appCoordinator.ts`，`main.ts`、`index.html`，以及 Goal repository/recovery、共享协议与 `server/dataStore.js`。

## 2. 固定用户可见的行为

| 场景 | 下一阶段行为 |
| --- | --- |
| 阅读书籍 A | 使用现有可调宽度 Sidebar；当前 Goal、树、原位编辑及关联摘录保持现有操作 |
| A 切换到 B | 保持同一 Goal、选中节点、树展开和材料展开状态；更新正文与页边笔记，不自动归入任何材料 |
| 在 B 归入高亮／笔记 | 归入当前 Goal，立即展开；原先来自 A 的材料仍在，计数包含所有有效直接关联 |
| 创建章节子 Goal | 章节是来源背景，记录书籍和章节；切书不删除或重建节点。阅读侧栏可提示当前来源相关的直接子节点，完整树始终可达 |
| 点击顶部 `Goals` | 提交当前编辑后进入 Goal 页面；主区显示当前 Goal，左侧 Goal 侧栏及分隔条完全隐藏，不留占位 |
| Goal 页面 | 一套 `All goals`／当前 Goal 导航、一处当前标题、一组新建入口、一份材料列表；查看或编辑当前节点时主区显示详情，打开完整树时在同一区域切换，不并排复制详情 |
| 在 Goal 页面切换节点 | 选择后展示该节点并展开材料；直接子节点不按当前打开的书或章节过滤 |
| 从 Goal 页面返回阅读 | 恢复之前的书籍、阅读锚点和侧栏宽度／收放偏好；从未打开书时显示普通书库入口，不强迫选择一本书才能使用 Goal |
| 点击跨书材料 | 打开该材料明确对应的书，调用原文定位，保留选中的 Goal；Goal 页面切回阅读视图，不弹新的引用面板 |
| 没有打开书 | 可以进入 Goal 页面、创建和编辑 Goal；没有可归入的来源时不显示关联动作 |

新界面继续使用简短英文，不全站翻译。跨书材料以次要、短书名标识来源；章节或长标题通过现有 title/可访问名称提供，不给每条材料堆叠时间、引用或状态标签。不新增筛选器、仪表盘、完成度、期限和成功 toast。

顶部 `Goals` 是页面导航，独立的侧栏图标是阅读区收放控制，两者各做一件事。进入 Goal 页面时侧栏图标不显示；返回阅读时尊重用户原来的收放偏好，不把“页面隐藏侧栏”写成用户关闭侧栏。

## 3. 最小实现边界

### 同一份 Goal 状态，同一个编辑器

- Goal 控制器维护全局 `selectedGoalId`、树展开、材料展开和草稿；当前书仍由现有 Session/Reader/Annotations 管理。应用启动载入 Goal，不再在每次切书时安装另一份 Goal 状态。
- 当前 Goal ID 作为应用偏好恢复，失效时回退到现有首个根节点／空状态；不把 UI 选择混进书籍备份。Goal 首次读取失败只禁用 Goal 写入并保留恢复内容，不清空原状态或阻止正常书籍加载。
- 增加最小页面状态 `reader | goals`，由 Goal 的展示协调代码维护；不新建通用路由框架、状态库或事件总线。
- 复用一个 `GoalUI` 和一个 textarea。提交编辑后把现有 Goal 根节点挂载到侧栏 host 或主区 host；禁止复制两份 DOM 再仅隐藏其中一份。
- Goal 主区使用应用字体、背景与正常内容宽度；阅读侧栏保留 280px 默认、220–640px 拖动、宽度记忆和键盘操作。主区宽度与侧栏偏好分开，不把全宽值写回侧栏。
- 阅读区进入后台时保留 DOM、阅读锚点和原笔记数据；忽略隐藏时的宽度 0/refit。返回时恢复现有排版流程，不重走导入或重新解析书籍。

### Goal 数据独立，来源仍明确

- 将当前 `BookGoalState` 提升为一份小型全局 Goal 状态，继续沿用 SQLite JSON、repository、串行队列、revision、幂等命令与恢复缓冲。
- Goal 节点无所属 `bookId`；可选 origin 记录产生它的书籍、源页／章节，独立页面创建的节点 origin 为 null。
- 迁移旧书内根 Goal 时，旧书 ID 可保留为来源背景；原来没有章节位置的节点留空，不伪造为第 1 章。这是来源线索，不恢复书籍所有权。
- 链接明确包含 `goalId`、`annotationId`、来源 `bookId` 及来源书籍 generation。书籍代次仅用于校验来源，不能再作为 Goal 本身的存活条件。
- 为 Goal 提供独立材料读取入口，复用现有 annotations repository/查询；跨书材料不装进 `AnnotationController.setNotesForBook()`，避免影响正文高亮、页边笔记筛选和导出范围。内容仍引用原记录，不另存正文副本。
- 当前书笔记更新时定点更新 Goal 摘录；其他书材料按关联来源读取，先呈现读取状态而非当作“没有关联”，读取失败不把计数静默减为 0。
- 当前 `goalChildren(..., sourcePage)` 必须增加来源书籍判断，避免 A 的第 1 章与 B 的第 1 章被当成同一上下文；已选中的节点不因来源不同而自动切走。

### 兼容与生命周期

| 边界 | 实施要求 |
| --- | --- |
| 现有 v2 数据库 | 同库事务式增量升级，新增不依赖书籍外键的全局 Goal 存储，保留原表用于核对和兼容，不重写书籍／标注 JSON；禁止把多书 Goal 仅在前端拼接成假全局状态 |
| 原有 Goal ID | 使用稳定的 `(旧 bookId, 旧 goalId) → 全局 goalId` 映射；迁移与导入旧备份使用同一规则，避免不同书的重复 ID 相撞，也避免反复导入产生副本。保留文字、层级、时间与来源 |
| 未确认写入／草稿 | 保留旧缓冲直至转换写入确认。已发出的命令不能直接更换 opId 或把旧书内 revision 当成全局 revision；服务端的 Goal 兼容处理先核查原操作是否已提交，再决定确认或转换，冲突和旧 generation 阻断并保留原缓冲 |
| 并发 | Goal 用独立队列和 revision，来源标注继续使用原同书队列。删除来源造成 Goal 关联变化时，接受新的 Goal revision；旧全量快照不得把已删除关联写回来，也不得清空后来新增的 Goal |
| 删除原标注 | 保留原删除语义；在同一事务清理全局 Goal 中该来源的链接，保留 Goal 节点及其他链接 |
| 删除一本书 | 原书及其标注照常删除，仅清理该书材料链接，保留 Goal 树和文字；bookRepository 不再清除整个全局 Goal 缓冲。旧书 generation 不能让残留请求关联到同 ID 的重建书籍 |
| 跨书定位竞态 | 冻结目标书籍、材料及当时的 Goal；沿用 `openBookRequestId` 防止迟到响应覆盖后来操作。打开后再验证材料存在并执行原定位；失败保留当前 Goal 和已有材料，不跳到第一章冒充定位成功 |
| 关闭和失败 | 新全局 Goal 缓冲纳入既有关闭握手；迁移失败或保存失败时保留输入，不能安装空状态再覆盖原数据 |

### 保持原导入导出操作，适配 Goal 的附加数据

EPUB/TXT 导入、原书籍与标注字段、章节 Markdown、笔记摘要、文件选择器和每书文件规则保持现状。需要修改的是 Goal 附加数据的兼容适配，不能继续把全局 Goal 硬塞进旧的每书 `goalStates` 归属语义。

新书籍备份使用向后可识别的版本与可选 Goal 图字段（建议 1.2）。每书导出仅携带与本书关联或来源本书的相关根 Goal 树，以及指向本文件标注的链接；不夹带其他书正文和标注。取消“包含高亮与笔记”时不输出材料链接，缺失链接仍不能解释为清空已有关系。

恢复时按全局 Goal ID 合并节点；只替换备份明确覆盖的书籍／节点关联，保留其他书的关联。旧 1.0 不含 Goal 时不清除现有 Goal；旧 1.1 通过稳定 ID 映射导入。合并后校验环、孤儿和来源，再在一个事务提交。HTTP 与桌面严格校验、完整性检查同步支持。

完全没有书籍来源和材料关联的独立 Goal，由现有 SQLite 一致性备份覆盖；每书 `.aurabackup` 不宣称是全部独立 Goal 的备份。本阶段不增加 Goal 导出菜单；实现记录须明确这个覆盖范围。

| 5. 回归与真实桌面验收 | 扩展既有模型、切书、Goal DOM、SQLite、备份、桌面与故障测试；更新 README 和实现记录 | 下方验收路径全部通过，截图能对照阅读与 Goal 两种页面；其他模块无额外功能或行为改动 |

## 5. 必须验收的路径

1. 在 A 创建父／子 Goal 并关联高亮和笔记，切到 B：同一选中节点、展开状态和 A 的材料仍在；再加入 B 材料，重启后完整恢复。
2. 进入 Goal 页面：全页只有一套 Goal UI；`#goal-panel`、`#goal-content`、textarea 等无重复 ID/实例，左侧栏和分隔条均不可见且不占宽度；当前 Goal 标题、材料列表、新建入口各出现一次。
3. 全局树、父级返回、子级选择、原位编辑与 IME 正常；Goal 页面显示全部直接子节点，阅读侧栏的章节上下文同时校验书籍来源。
4. Goal→原文定位 A/B→返回 Goal：原意图不变；快速连续点击两个来源时只执行最后有效导航，缺失来源有明确反馈。
5. A→B 的未确认笔记写入与 Goal 归入并发，固定归入原目标；失败保留内容，不向后来打开的书误归入。
6. Goal 页面不依赖当前书：空书库、未打开书、双页偏好和窄窗口都能进入；返回阅读后原模式与侧栏宽度／收放偏好恢复。
7. 旧 v2 库、重复旧 Goal ID、未提交草稿、失响应命令、旧 generation、冲突、只读和 Renderer 恢复均不丢数据；迁移失败不写空库。
8. 两个每书新备份往返、分次恢复、不含标注、旧 1.0/1.1、无书 Goal 的 SQLite 完整备份均符合上述边界；坏树或断链整笔回滚。
9. 既有高亮颜色／范围与独立删除、笔记点击编辑／外部保存、导入、章节与摘要导出、书库、目录、排版及字体测试继续通过。

实施验证命令沿用 `npm run typecheck`、针对性用例、`npm test`、`npm run test:desktop`；因本阶段涉及 Goal 存储迁移和关系清理，还需重跑包含跨书 Goal 的 `npm run test:stability`。计划撰写不计为这些新检查已通过。

本阶段不增加 Workspace/Compact 两种独立布局、Goal 独立文字条目、点赞点踩、AI、拖拽、Goal 删除／移动／排序或新的知识图谱。当前工作是完善同一个 Sidebar 方向中的跨书延续和独立主区。
