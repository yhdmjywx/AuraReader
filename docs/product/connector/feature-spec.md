# AuraReader 本地 Connector MVP

2026-11-23 · 初始产品需求 · 待实现

读者可以在同一台设备的 ChatGPT 或 Codex 对话中，查阅 AuraReader 书库里的完整正文和自己的阅读记录，也可以把讨论写回原文旁或指定 Goal 下。由读者决定操作哪本书、哪段原文或哪个 Goal。助手无需感知阅读器当前打开的 Goal。

## 接入范围

- MVP 覆盖本机书库现有的数据和操作。AuraReader 关闭时仍可读写，重新打开后能看到已保存的结果。
- **实施假设**：默认接入 Electron 桌面书库。桌面版和浏览器版各有独立的 SQLite 书库；已确认的是本设备访问，双库切换尚未定为需求。见[数据与备份](../../data-and-backup.md)。
- 云端、跨设备访问和 Skills 留待后续。具体接入协议、工具名称和客户端打包方式由实现设计确定。

## 功能范围

| 对象 | 读者可以查询 | 读者可以操作 |
| --- | --- | --- |
| 书籍 | 书目、目录、完整正文，以及某条引文在书中的位置和前后文 | 导入本机 EPUB／TXT、管理书籍，使用已有的导出和备份恢复功能 |
| 高亮与页边笔记 | 包括尚未关联 Goal 的标注。分别提供原文引句、读者评论、来源书籍及位置 | 按现有读写能力在指定原文处创建和管理标注，包括编辑笔记、关联或解除关联。对话中新建高亮的优先级低于写笔记 |
| Goal 与书籍组织 | 无书 Goal、Goal 原文与层级、状态、主动添加的书籍，以及关联材料的来源书籍 | 创建或改写 Goal、建立子 Goal、添加或移除关联书籍和材料，执行现有的完成、归档、删除、恢复和彻底删除操作 |
| Goal 内容与 Response | 该 Goal 拥有的自输入、跨书高亮和笔记，保留现有内容顺序与 Response 标记 | 新增、编辑或删除自输入，在指定 Goal 中标记或取消 Response |

主动把一本书添加到 Goal、把书中的一条笔记关联到 Goal，是两个独立操作。子 Goal 有自己的书单。材料的 Response 随它和具体 Goal 的关联保存；同一笔记可以在一个 Goal 下标为 Response，在另一个 Goal 下保持未标记。见[Goal 与书籍关系](../../archive/plans-and-implementation/goal-books-module-design.md)及 [Response 行为](../goals/user-input-response/response-implementation.md)。

## 写入与同步

用户用自然语言指定写入形式和位置：

- “把刚才关于这段原文的讨论写到『友谊如何维持』Goal 下。”在该 Goal 中新增一条自输入。
- “把刚才的讨论作为《某本书》中『某段原文』的笔记。”在指定原文处新增页边笔记。

Connector 收到明确指令后即时执行。MVP 不设独立权限管理、强制预览或二次确认流程；个人操作习惯可由用户在 prompt 或 `AGENTS.md` 中约定。

双方以成功保存的内容即时同步。Connector 的写入应直接出现在已打开的 AuraReader 中，保留当前滚动位置和正在编辑的草稿。读者在 AuraReader 保存后，助手下一次查询即可读到新内容。

**同一条笔记出现并发编辑时，沿用现有保存冲突行为。** 若助手先写入，而读者随后提交基于旧版本的草稿，AuraReader 保留草稿并提示笔记已更新。正常写入直接生效。

## 初始验收场景

| 场景 | 预期结果 |
| --- | --- |
| 关闭 AuraReader，从对话读取一本书的指定章节，再向无书 Goal 添加自输入 | 可读取完整章节；重开 AuraReader 后能在指定 Goal 看到记录 |
| 同一段讨论分别要求“写到 Goal 下”和“作为这段原文的笔记” | 前者产生 Goal 自输入；后者产生可定位回指定引文的页边笔记 |
| 同一条笔记关联两个 Goal，只在其中一个标记 Response | 分别查询两个 Goal 时，原文与评论一致，Response 各自正确 |
| 双方同时打开，从助手新增一条自输入，再从 AuraReader 修改它 | 当前界面立即显示新增记录并保留阅读位置；助手下次查询读到已保存的修改 |
| 读者正在编辑笔记，助手先修改并保存该笔记，随后读者保存旧草稿 | 已保存的修改可读，旧草稿得以保留，AuraReader 提示冲突 |
