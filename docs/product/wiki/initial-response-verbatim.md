你的“**选中文字 → 点击 Wiki → 弹出查询窗口**”可以保留。需要补齐的是窗口内部的两项能力：**匹配词条，以及选择百科语言版本**。

我已阅读项目的 [AGENTS.md](E:/dp/reader_workstation/AGENTS.md)、[project-profile.md](E:/dp/reader_workstation/docs/agents/project-profile.md) 和设计规范。现有阅读界面已经有 `Highlight / Note` 选区操作入口，适合在这里增加 `Wikipedia`。设计索引中也能定位到 Selection Actions，但尚未记录 Wiki 窗口设计，下面是行为建议，不是已批准的视觉方案。本轮未修改项目。

**1. 选中的文字，不需要刚好等于词条名**

先澄清你举的例子：“蛋壳”实际上有独立的[中文词条](https://zh.wikipedia.org/wiki/蛋壳)，并且关联了英文 [Eggshell](https://en.wikipedia.org/wiki/Eggshell)。不过你担心的情况确实存在，比如选中了“坚硬的蛋壳”、某个变体写法，或者一个有多种含义的词。

建议将选中文字作为**初始查询词**，按照下面的规则处理：

| 遇到的情况 | 窗口如何表现 |
|---|---|
| 命中明确词条，或维基已有的别名重定向 | 直接显示词条标题和简介 |
| 命中消歧义页，存在多个意思 | 显示候选词条及简短说明，让用户选择 |
| 没有同名词条，但有相关搜索结果 | 展示候选列表，不自动把第一条当作答案 |
| 没有结果 | 保留查询文字，允许修改后重搜 |
| 请求失败或无法联网 | 显示加载失败与重试，不说“没有这个词条” |

这些基础能力不必依赖 AI。MediaWiki 提供了[重定向解析](https://www.mediawiki.org/wiki/API:Query#Resolving_redirects)和[标题／正文搜索](https://www.mediawiki.org/wiki/API:Search)。

例如选中“坚硬的蛋壳”，可以搜索完整文字，展示可能相关的词条；用户也能直接在窗口中把它改成“蛋壳”。**不要悄悄把“蛋壳”截成“蛋”再打开**，因为这已经改变了查询对象。

即使命中了同名词条，也建议保留“其他结果”入口：字面匹配不代表一定符合书里的含义。

**2. 中文选词、查看英文百科：优先通过词条关联切换**

这里需要区分三个东西：

- **选中文字的语言**：例如书中的“蛋壳”。
- **希望阅读的百科版本**：例如 English Wikipedia。
- **应用界面语言**：项目目前规定界面使用英文，不应因此强制查英文百科。

对你的问题，我建议：**优先找到对应概念，再使用维基已有的跨语言关联；翻译查询词作为找不到对应关系时的补救。**

例如：

> 选中“蛋壳” → 识别到中文“蛋壳”词条 → 取得其英文关联 → 显示英文 Eggshell。

这里**不需要先让用户看到中文页面，再手动切一次英文**。如果用户已经选定英文，应用可以在后台完成中文词条匹配，直接展示英文结果。MediaWiki 的 [Langlinks API](https://www.mediawiki.org/wiki/API:Langlinks) 可以取得页面对应的其他语言链接。

这样做的理由是：普通翻译得到的英文词，不一定就是维基的正式词条名，也可能把多义词翻错。已有的跨语言关联更适合作为首选依据。

需要明确处理两个例外：

| 情况 | 建议行为 |
|---|---|
| 找到了中文词条，但没有关联的英文条目 | 明示“没有关联的英文版本”，提供“查看中文”与“在英文维基搜索” |
| 中文本身也找不到对应词条 | 允许修改查询词，或使用翻译后的英文词搜索候选结果 |

“没有关联的英文版本”**不等于**“英文维基一定没有相关内容”。所以仍然应该允许搜索。若后续加入自动翻译，翻译词应显示出来并允许修改，不要把翻译后的第一条搜索结果直接当成已确认的对应词条。

另外，**切换到英文百科**与**把中文条目翻译成英文**是两个不同功能。你现在提出的需求属于前者。

**3. 放到 AuraReader 中，第一版可以很简单**

建议的完整操作是：

1. 用户选择文字，在现有选区操作栏点击 `Wikipedia`。
2. 应用内弹出查询窗口，保留原来的阅读位置。
3. 窗口顶部显示可编辑查询词和百科语言选择，例如 `蛋壳`、`English`。
4. 明确命中时直接显示简介；有歧义或匹配失败时显示候选列表。
5. 提供查看完整条目的入口；关闭窗口后继续阅读。

语言默认规则建议采用：

- 用户曾经选择过百科语言：记住并优先使用。
- 首次使用：默认跟随书籍语言；无法确定时使用系统语言，并始终显示当前选择。
- 在一个已打开的条目里切换语言：优先打开这个条目关联的语言版本，保持查询对象一致。

这样，用户只要选过一次 English，后续即便读中文书，也可以继续优先查看英文百科。

窗口第一版只需要**查询框、语言选择、结果区域、完整条目入口、关闭**。自动翻译不是完成第一版的前提；跨语言关联找不到时，先支持手动输入英文搜索就能形成完整流程。

**4. 类似阅读器的参考**

[KOReader 官方用户指南](https://koreader.rocks/user_guide/)记录了：长按文字后，可以在弹出的查询对话框中查词典、搜索文档或查询 Wikipedia。这支持你的入口判断——百科查询适合紧邻选中文字，而不是藏在全局设置里。

对于 AuraReader，我更建议保留独立的 `Wikipedia` 操作，直接进入百科窗口，避免为了查百科先经过词典。

这轮最值得确定的产品原则是：**正常命中时一键看到内容；不确定时给候选和修改入口；跨语言优先沿用词条关联。** 它能同时解决你提出的两个问题，也不要求第一版就具备复杂的语义识别或翻译能力。
