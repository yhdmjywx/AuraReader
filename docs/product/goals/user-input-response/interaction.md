# Goal 用户自输入与 Response：交互约定与组件整合

日期：2026-11-10。

状态：Figma 模块与状态保持原记录；自输入和区域 UI 已接入源码中的侧栏及现有完整 Goal 工作区，见[实现与验证](implementation.md)。Home 工作区入口由用户明确留待后续。

Response 补充：用户选择 Readwise Reader 风格的标签图标与左侧选项菜单，当前交互需求见第 5 节。Figma 菜单与反馈主件搭建因 MCP Starter 额度上限中断，UX 组合与验收未完成，见第 6 节。原自输入整合记录保留历史语境；Response 现已接入源码，按关联保存和恢复，实际检查见 [Response 实现记录](response-implementation.md)。

## 1. 本轮用户确认

- 分支图标、叠层文档图标暂时仅作区域标识，不执行动作，不提供折叠。
- 自写内容为多条独立文字记录，每条允许换行。
- MVP 中，自写内容属于创建它的 Goal，不自动成为可跨 Goal 共享的原始标注。

以上确认补充[功能需求](feature-spec.md)，没有改变已有 Highlight、Note 可被多个 Goal 关联的关系。

## 2. 继承现有设计系统的交互

本轮用户指定以[设计系统](../../../design/design-system.md)作为 UX 来源。Goal 内的自写内容沿用同区 Goal 的原位编辑方式；删除操作复用现有笔记的明确删除动作，不新增生命周期系统。

| 场景 | 约定 |
| --- | --- |
| 新建 | 点击当前 Goal 内容区的“文档＋”，在已有内容之前出现一条原位草稿；已有内容仍保留。未进入具体 Goal 的根层级不提供自输入入口 |
| 多条记录 | 一次新增对应一条独立记录；记录内部可以换行，不将每段文字自动拆成另一条内容 |
| 输入 | 编辑器与显示文字保持相同原点、宽度和字体，随文字增高，不添加独立弹窗或常驻 Save/Cancel 区 |
| 换行与结束 | Enter 换行；失焦、Escape、Ctrl/Cmd+Enter 结束编辑并自动保存。Escape 不撤销已保存文字 |
| 中文输入 | IME 组合期间不因上述按键提前结束；实现时保持光标、选区与输入节点稳定，不触发正文翻页快捷键 |
| 空白新草稿 | 结束编辑时为空则丢弃，不生成空白记录 |
| 已有记录 | 编辑图标进入原位编辑；沿用 Goal 区对已有内容的保护：结束时清空不隐式删除，恢复最近非空内容。删除使用明确动作 |
| 行操作 | hover、键盘焦点或对应操作开启时显示编辑、删除；无 hover 的设备保持可访问。动作覆盖匹配的行背景，不因显示动作改变正文宽度；编辑中隐藏动作 |
| 删除 | 明确点击 Delete text，删除当前自写记录。参照现有笔记的直接删除方式，本轮未添加确认弹窗、回收站或新 Undo 机制；其他记录和来源标注不受影响 |
| 位置 | 新加入的记录在上；编辑既有记录不更新其加入顺序。Response 的已有 MVP 规则保持不变 |
| 保存失败 | 保留文字并显示持续可见、可关闭的错误反馈，提供 Retry。关闭反馈不表示保存成功，也不丢弃待保存内容 |
| Goal 切换或关闭 | 沿用现有结束编辑和保存检查；保存失败时保留输入，不将未确认写入当作可靠保存 |

页边笔记的“Enter 结束、Shift+Enter 换行”和红色自定义光标属于其局部例外，没有扩展到 Goal 自输入。

## 5. Response 标签入口与菜单（需求补充）

本节是本次确定的 Response 交互要求，补充[功能需求第 5.6—5.9 节](feature-spec.md#56-标签入口与适用对象)。用户明确选择图标入口、左侧 Response 菜单、自然过渡与独立组件；下述局部尺寸、键盘和保存反馈按现行项目约定补齐。本节不修改已完成的自输入行为，也不将原自输入 Error 状态当作 Response 保存反馈已实现的证据。

### 5.1 入口与基本操作

| 场景 | 要求 |
| --- | --- |
| 行操作布局 | 自写条目中，标签图标放在编辑按钮左侧，编辑与删除位置保留；材料沿用自身动作。采用既有 28px 紧凑目标、16px Remix 图标与 8px 按钮圆角；不因行操作显隐重排正文 |
| 入口显隐 | hover、键盘焦点或菜单打开时可见；非 hover 设备可直接访问。编辑期间隐藏行操作；新草稿先完成保存，再允许标记 |
| 可访问名称 | 图标按钮名称和 tooltip 为 Response，没有常驻 Mark Response／Mark as Response 文字；标签图标不使用完成勾或图钉替代 |
| 点击入口 | 打开／关闭该条目的菜单；不直接添加或取消标签，不触发正文编辑、来源跳转或删除 |
| 菜单选项 | 只有 Response 一项，以选中状态表达是否已标记；使用 menuitemcheckbox 语义，文字左对齐，右侧预留稳定的选中指示位置，无搜索、管理标签、分组或新建入口 |
| 选择未选中项 | 添加标记，立即显示浅灰内容块和加强标签，自动关闭菜单并提交保存 |
| 选择已选中项 | 取消标记，移除浅底和展示标签，自动关闭菜单并提交保存；选项名称仍为 Response |
| 关闭而未选择 | Escape、外部点击、再次点击入口只关闭菜单，不改变标签。一次只开一个标签菜单，打开其他条目时关闭前一个 |
| 菜单与标记状态 | aria-expanded 表示开闭，菜单项 aria-checked 表示标签状态；图标按钮不使用 aria-pressed 冒充标签切换。打开菜单沿用中性浅色反馈，不变成深色实心激活按钮 |
| 展示标签 | Response Label 是固定文字展示组件，不可点击，也不增加叉号。它与原文引文、评论及来源一起属于外层内容条目 |

### 5.2 位置、尺寸与过渡

- **默认定位**：菜单在图标左侧，菜单右缘距入口左缘 5px，首个选项的中心与入口垂直居中；浮层覆盖页面，不占列表布局空间。绑定真实入口，随所在容器滚动／窗口变化更新定位，不使用脱离条目的固定坐标。
- **边缘避让**：优先保持左侧并在视口内移动；左侧空间确实不足时允许向右回退。不得被侧栏的 overflow 裁切、遮住选项或产生页面横向滚动；目标移除、隐藏或切换 Goal 时关闭菜单。
- **紧凑样式**：使用既有白色／中性菜单表面、边框、轻阴影与约 9px 浮层圆角。文字 13px／1.4，选项上下 8px、左右 10px，菜单内边距 5px；内容适配宽度，基准约 128px，并随文字缩放保持可读。此宽度仅用于 Response 菜单，不改共享菜单的默认宽度。
- **反馈**：选项 hover 和键盘高亮使用既有中性浅灰，选中指示与 hover 分别表达状态；选中项仍可点击取消，不因已选中而禁用。
- **动画**：复用项目现有 `--ui-motion` 的 140ms、`cubic-bezier(.2,.7,.2,1)`，从靠入口一侧的原点以 opacity 0→1、scale .97→1 打开，关闭反向过渡。向左由浮层定位表达，不平移正文、不使用弹跳或重复动画。
- **减少动态效果**：遵循系统 prefers-reduced-motion，直接完成显隐；动画不阻塞焦点或点击，快速开闭最终状态正确。

### 5.3 键盘、焦点与无 hover 设备

- 入口是可聚焦按钮，Enter／Space 打开菜单，焦点进入唯一的 Response 选项；提供菜单关联名称和展开状态。
- 菜单沿用现有基础组件的方向键与 Home／End 行为，Enter／Space 切换选中并关闭；不新增 T 或其他产品快捷键，也不劫持阅读器或编辑器按键。
- 选择、Escape 或再次点击入口关闭后，焦点回到仍存在的入口；Tab 关闭并继续正常导航。外部点击保留所点击位置的焦点，不强制抢回入口。
- 如果关闭原因是切换 Goal 或目标消失，不向旧入口强行恢复焦点；沿用新视图的焦点处理。
- 鼠标从入口移动到菜单时菜单保持打开；不因离开正文 hover 区而消失。无 hover 设备可点击入口和选项，不要求先悬停或长按。

### 5.4 状态反馈与保存

| 状态 | 可见反馈与行为 |
| --- | --- |
| 未标记 | 正文保持原呈现；菜单 Response 未选中；打开菜单不会改变它 |
| 已标记 | 浅灰内容块与加强标签常显，菜单 Response 选中；内容类型、来源和原顺序保留 |
| 待保存 | 呈现用户最新目标状态，复用轻量行内状态区提供 Saving… 反馈并声明忙碌状态；入口仍为标签图标，不新增保存按钮或菜单项 |
| 保存成功 | 清除该次匹配的待保存反馈；不弹成功对话框；刷新后读到已确认结果 |
| 保存失败 | 保留最新选择和待写信息，显示 Couldn’t save Response.、Retry 与错误关闭动作；错误位于对应条目，独立于正文编辑错误，不改变正文 |
| 关闭错误反馈 | 只隐藏提示，不清除待写信息或确认保存；待保存状态仍可识别，沿用未保存检查 |
| 重试或再次选择 | Retry 提交最新目标状态；用户也可重新打开菜单改变选择。旧确认或旧错误不得覆盖之后的选择，多个结果按对应操作归属处理 |
| 不可编辑 | Goal 归档／删除、材料不可操作或整体禁用时禁止标记；已保存的 Response 外观保留，不因禁用而自动取消 |

交互目标始终为发起时的 Goal 与内容。切换 Goal 关闭菜单，但不把待保存操作转移到新 Goal；条目删除／解除关联后，延迟结果不得重建该条目或空标签块。选项状态和正文旁的标记呈现遵循同一个最新选择，不能出现菜单已取消而条目仍被当作已标记的相反反馈。

正文编辑沿用既有保存行为；本次只要求 Response 状态复用同一保存与恢复基础，不另建保存服务。既有生命周期与备份政策不在本次菜单需求中扩展；涉及解除后重新关联、备份合并时的 Response 元数据细则，须在后续架构中按既有关系规则明确并记录。

### 5.5 独立组件与后续状态稿

| 组件职责 | 本次要求 |
| --- | --- |
| Response Label | 复用现有 Figma 主件，仅展示标签；不承担菜单和保存动作 |
| 标签操作组件（建议命名 ResponseTagControl） | 独立组织图标入口、锚点菜单及 Response 选项；接收所属内容、选中、可编辑、待保存和错误状态，发出明确的目标选择 |
| 共享菜单／按钮基础 | 复用现有组件的定位、焦点、键盘、Portal 和中性样式，补齐可切换菜单项；局部支持左侧定位与紧凑宽度，不改其他菜单 |
| Goal Content Item | 容纳既有内容与 Response 外观，协调原行操作；不把全部正文状态复制成标签变体，不改变 Highlight／Note 主体行为 |
| List／Panel | 沿用原内容顺序、导航及共享状态；不新增 Response 分组、筛选、排序或独立页面 |

后续 Figma 须在现有三类内容组合中补齐：图标默认／hover／焦点、菜单未选中／已选中、关闭与重开、保存中／失败／重试、禁用，以及左侧定位与边缘回退。现有的自输入状态实例继续保留；新菜单状态不能只用已存在的正文 Error 示例代替。

### 5.6 参考与证据边界

- [Readwise Reader：Organizing Content](https://docs.readwise.io/reader/docs/organizing-content) 明确支持选中高亮后，从标签图标进入标签操作。本次采用这一模式，不复刻其多标签、搜索、新建标签或过滤功能。
- 左侧展开来自本次用户要求；5px 间距来自项目既有浮层实现，140ms 动效来自既有 workbench motion token。它们是本项目适配值，没有宣称是实测的 Readwise 像素或动画参数。
- 本节最初形成时仅更新文档，Figma Label／Item／List／Panel 当时是结构及外观基础；后续菜单 UX 部分交付见第 6 节，应用保存链路仍未接入。后续构建、真实界面操作、刷新、失败恢复及键盘验收按功能需求第 7 节执行。
