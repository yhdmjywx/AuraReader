## 1. 目标与产品依据

Goal 表达读者自己的意图，可以独立于书籍、高亮和笔记存在，并随阅读持续改写、展开。内容与 Goal 的关系由用户主动决定，产品不预设意图的形式或最终产出。

本 MVP 补充用户直接在 Goal 节点下创作内容的能力，并让用户用可选的 `Response` 标签表达内容在当前 Goal 中的作用。

产品必须提供用户自输入能力；用户不必在每个 Goal 中输入内容，也不必创建 Response。

## 3. 支持的使用方式

两种方式可以独立使用，也可以在同一个 Goal 中并存，不要求用户预先选择模式。

### 3.1 保留 Goal，在其下记录内容和回应

例如，保留“企业家精神是什么？”，在其下关联高亮、笔记，或直接写自己的理解。用户可以将其中的内容标记为 Response，也可以保持无标签。

### 3.2 直接改写 Goal，表达新的理解或方向

例如，用户开始写下“I want to make a friend.”，阅读和标注后将同一 Goal 改为“找到一个分享和谈论书的朋友。”

改写 Goal 仍是现有能力，不要求先创建 Response，也不因改写自动完成 Goal、改变内容关联或创建新的 Goal。

## 4. 用户自输入与统一内容组织

### 4.1 直接创作

- 用户可以在 Goal 节点下直接创建、编辑、保存和删除自己的内容。
- 自写内容独立于 Goal 标题；修改它不等于修改 Goal，也不等于创建子 Goal。
- 不要求先选取原文、创建书中 Note 或关联书籍。
- 用户可以只记录想法，不打标签，不将其定义为答案。
- 已有 Note 同样可能是用户自己的思考；User Input 与 Note 的区别在于直接在 Goal 中创作，无须依附原文。
- 自写内容由多条独立记录组成，每条允许换行；MVP 归属于创建它的 Goal，不自动与其他 Goal 共用同一自写记录。
- 自写内容随所属 Goal 归档、删除、恢复而保留和恢复；彻底删除 Goal 时一起清除。归档或删除状态下不可新增、编辑或直接删除所属自写记录。
- 自写内容不进入逐书 `.aurabackup`；逐书恢复不清除目标库中已有的自写记录，整库 SQLite 一致性备份覆盖这些记录。

入口位于内容区顶部；采用 02 方案后，使用“文档＋”图标表示新增自写内容，取代此前的 `Add text` 文字入口。新增、原位输入、编辑、删除及失败反馈依据现行设计系统整合，详见[交互约定](interaction.md)。

### 4.2 统一呈现

- 移除 Goal 区内将关联材料单独包围的 Linked 分组及其分组标识。
- User Input、Highlight、Note 在当前 Goal 下共同呈现，不再按“关联材料／用户自输入”分成两个独立组。
- “同一大组”描述内容组织，不抹去来源、对象类型和操作语义，也不自动确定自由混排或拖拽能力。
- 子 Goal 保留其层级与导航身份。它可以与内容处于同一父级区域，但不能被当作普通文本条目。
- 统一内容区沿用原 Link 分组的布局位置，位于子 Goal 下方。顺序为：当前父 Goal、直接子 Goal、统一内容区。
- 沿用布局位置不表示恢复 Linked 分组标识，也不要求改动 Highlight、Note 的 Link 组件。
- 子 Goal 与统一内容区之间使用细水平分界线；子 Goal 区以分支图标识别，内容区以叠层文档图标识别，内容区顶部右侧为“文档＋”新增入口，不增加模块标题文字。
- 不使用树枝连线、左侧括线或贯穿内容区的层级导引线；已有引用内容自身的竖线保留。字体沿用原 Figma，父 Goal 保留稍加粗文字，不加目标图标。当前静态呈现见[设计记录](design.md)。
- 分支与叠层文档图标暂时仅作区域标识，不触发折叠或其他动作；本轮不提供由这些图标控制的内容折叠。
- 内容采用栈式顺序：新加入当前 Goal 的内容显示在统一内容列表最上方，位于已有内容之前，不越过子 Goal 区域。
- 对已有 Highlight、Note，“加入”指归入当前 Goal，而非原标注的创建时间；对 User Input，指在当前 Goal 中新建内容。编辑已有内容不视为新加入。
- 上述顺序是统一内容的基础顺序。MVP 标记 Response 不改变该顺序；后续联动置顶时，按第 5.4 节的优先展示规则排列。

### 4.3 Link 组件保留边界

需要移除的是 Goal 区的 Linked 分组组织与分组标识，不是 Highlight、Note 的 Link 组件。

- 保留 Highlight、Note 既有的 Link 组件及关联操作。
- 保留关联内容现有的来源展示、原文定位、编辑和解除关联语义。
- 不因移除分组而重做、替换或改变这些组件的原有行为。
- Response 操作按第 5.6—5.9 节接入条目操作区；不将标签需求解释为重做现有 Link 组件的授权。

### 4.4 统一呈现后仍需识别的区别

| 对象或动作 | 必须保留的含义 |
| --- | --- |
| 原文引文 | 能辨认来自书籍的原文，保留来源关系与定位能力 |
| Note 与直接自写内容 | 能辨认已有笔记与直接在 Goal 中创作的内容；具体识别方式待设计 |
| 将 Highlight、Note 移出 Goal | 解除当前关联，原高亮或笔记仍保留 |
| 删除 Goal 下自写内容 | 删除该自写内容，不伪装成仅解除书中标注的关联 |
| 子 Goal | 仍可进入并继续展开自己的意图和内容，不与普通内容条目混淆 |

## 5. Response 标签

### 5.1 MVP 标签范围

- MVP 仅由产品提供 `Response` 标签。
- 不提供用户自定义标签，也不预设其他内容分类。
- 标签可选。创建、关联或保存内容时，不要求先选择标签。
- 产品文案使用 `Response`；用户输入和书籍内容保留原语言。

### 5.2 含义与适用内容

Response 表示：“在当前 Goal 下，用户将这条内容视为一种回应。”

- Highlight、Note 和 User Input 都可以由用户标记为 Response。
- 用户可以添加或取消标记；取消标签不删除内容或解除其关联。
- Response 不限于新写的文字，也不要求用户把原材料复制为新文本。
- 可以存在多条、暂时的或不同方向的 Response；它不表示最终答案，也不自动将 Goal 标为完成。
- 子 Goal 是否适用内容标签未获确认，不从内容标签需求推导新的子 Goal 行为。

### 5.3 标签按当前 Goal 生效

同一条高亮或笔记关联到多个 Goal 时，Response 在各 Goal 下分别标记。

例如，同一条高亮在 Goal A 下被标记为 Response，在 Goal B 下可以保持无标签。对 A 的标记或取消标记不改变 B，也不将该标签变成原高亮或笔记的全局属性。

### 5.4 标签、分组与置顶

- 默认保持统一内容列表，通过标记识别 Response，不自动建立独立 Response 分组。
- 本 MVP 不因引入标签自动增加标签筛选、排序模式或专门的 Response 页面。

#### 5.4.1 MVP：仅标记，不联动置顶

- MVP 中，添加或取消 Response 标签不改变内容位置，内容仍按加入当前 Goal 的时间新者在上排列。
- 实现需为后续联动置顶保留代码可扩展性，能够区分内容加入顺序与 Response 标记时间顺序；不将两者耦合成无法扩展的固定排序规则。
- 保留扩展能力不表示在 MVP 中启用联动置顶。

#### 5.4.2 后续联动置顶：已确认的展示规则

以下规则已获用户同意，供后续联动置顶实现使用，不改变 MVP 仅标记的范围：

- 标记为 Response 后，内容移到当前 Goal 的内容列表顶部。
- 置顶范围限于当前 Goal 的统一内容列表，仍位于子 Goal 下方。
- 多条 Response 按标记为 Response 的时间排列，新标记者在上。
- Response 持续优先于普通内容；普通内容继续按加入当前 Goal 的时间新者在上排列。
- 例如，基础顺序为 C、B、A，将 A 标记为 Response 后为 A、C、B；随后新增普通内容 D，顺序为 A、D、C、B。

### 5.5 标记与编排的边界

多条内容都标记为 Response，表示用户将它们视为回应，不自动合成为一篇连续正文。

在多段引文之间插入论述、自由调整内容顺序、将多条内容编排成一份连续表达，仍需单独明确交互与范围。

### 5.6 标签入口与适用对象

- 在当前 Goal 的 Highlight、Note、自写内容条目操作区提供一个标签图标按钮。自写内容放在原编辑按钮左侧，保留原编辑／删除位置；材料条目接入自身已有操作区，保留来源跳转、编辑及解除关联动作，不另造一套材料编辑器。
- 入口只显示标签图标，没有 `Mark Response`、`Mark as Response` 或其他常驻按钮文字。图标采用现有 Remix 家族，可访问名称及 tooltip 使用 `Response`。
- 入口复用现有紧凑行操作尺寸、hover／焦点反馈及显示规则；菜单打开时保持可见，无 hover 的设备提供可见入口。加入入口不挤压正文或造成显示／编辑文字的横向跳动。
- 点击入口只展开／收起菜单，不直接改变标记，也不触发编辑、原文跳转或解除关联。菜单展开状态与 Response 是否已标记是两个独立状态。
- 已保存且可编辑的内容可操作。新建草稿、正文编辑期间不提供可操作入口，沿用现有编辑中隐藏行操作的约定；Goal 归档、删除或内容不可编辑时禁用，不丢失已保存的标记。
- 自写内容和材料保留各自身份；Note 的引文、评论及来源属于同一条目，Response 外观包围整个条目。子 Goal 不加入该入口。

### 5.7 左侧菜单与标记／取消

1. 点击标签图标，在其左侧打开紧凑菜单，菜单只包含一个可切换的 `Response` 选项，不包含搜索、创建标签、标签管理或其他标签类型。
2. 当前条目未标记时，`Response` 未选中；点击该项后添加标记。已标记时，同一选项显示选中指示；再次点击则取消标记。选项名称始终是 `Response`，不改成第二个删除命令。
3. 使用带选中状态的菜单项表达是否标记；正文旁的 `Response Label` 只展示结果，不兼任按钮，也不增加单独的叉号删除入口。
4. 选择后自动关闭菜单并保存；不增加 Save／Apply 按钮或确认弹窗。点击外部、再次点击入口或按 Escape 只关闭菜单，不改变标记。
5. 标记后呈现已选定的浅灰内容块与加强标签；取消后移除这两项呈现，保留正文、来源、原有操作和列表位置。多条 Response 继续在统一列表中显示，不触发分组或置顶。

菜单默认向左展开，正常布局中菜单右缘距入口左缘 5px，首个选项与入口垂直居中。菜单使用项目现有中性色、字号、圆角和轻阴影；采用紧凑的内容适配宽度，目标约 128px，不沿用无必要的宽标签管理面板。接近视口边缘时进行碰撞避让，左侧确实容纳不下时才允许回退到右侧；不得裁切或产生横向滚动。具体焦点、尺寸与动效见[交互约定](interaction.md#5-response-标签入口与菜单需求补充)。

### 5.8 保存、状态反馈与一致性

- 选择后立即显示用户的目标状态，沿用现有 Goal 自动保存与恢复链路；等待保存确认期间提供轻量行内待保存反馈，不新增成功弹窗，也不将菜单关闭当作保存成功。
- 保存失败时保留最新选择与待保存信息，显示 `Couldn’t save Response.`、`Retry` 和可关闭反馈。关闭反馈不清除待保存状态，也不伪装为已保存；反馈不得改写或清空正文。
- 再次选择、快速标记／取消或失败后重试，以用户的最新选择为准；旧保存结果不得覆盖后续选择。Retry 重试最新状态，不重放过时的相反选择。
- 操作目标固定为发起时的 Goal 与内容身份；菜单开启后切换 Goal、移除条目或使条目不可编辑，应关闭失效菜单。未确认的保存继续按原目标处理，不能写入后来选中的 Goal。
- 同一 Goal 的侧栏与现有完整工作区共享标记状态；重开或刷新后保留已确认的结果。同一材料在其他 Goal 中的标签不受影响。
- 取消标签只移除该 Goal 下的 Response 身份；删除自写记录时移除整个内容条目，解除材料关联仍保留原标注。本轮不新增独立标签回收站或改变既有归档、删除、恢复及备份政策。
- 2026-11-10 用户明确：Response 跟随当前 Goal 下的关联保存；恢复原关联（包括备份中的原关联）时保留，新建关联时重新判断。解除后经关联入口重新加入属于新关联，默认不标记，不从原标注或其他 Goal 自动继承。

### 5.9 独立组件与交付边界

- 沿用已建立的 `Response Label`、`Goal Content Item`、`Goal Content List`、`Goal Content Panel` 分层；独立的标签操作组件负责图标入口、菜单和选中状态，复用现有按钮与菜单基础组件。标签展示、菜单开闭、正文编辑和保存状态分别管理，不扩展成所有状态的组合变体。
- 本节约定需求，不代表菜单状态稿或应用功能已完成；Figma 当前部分交付状态见本文开头。完整状态稿应至少覆盖未标记／已标记、菜单展开、hover／键盘焦点、待保存／保存失败／重试和禁用；三类内容复用同一操作约定。
- Readwise 参考仅用于「当前内容旁的标签图标进入标签选择」模式。其搜索、多标签、自定义标签、标签筛选及快捷键不进入本 MVP；向左展开是用户本次明确要求，5px 间距与 140ms 动效是项目本地适配值。

## 6. 对现行约定的影响

- 取代现行设计系统中 Goal 区 Linked 分组标识及其独立展开入口的要求；侧栏及现有完整 Goal 工作区的源码已接入统一内容区。
- 现有 Highlight、Note 的 Link 组件和材料关系继续有效。
- Goal 的创建、改写、父子导航、跨书来源、原文定位，以及侧栏和完整 Goal 工作区共享内容的原则继续有效。
- 内容区位于子 Goal 下方，采用新加入在上的基础顺序；02 模块现已融入原 Goal Sidebar，常态依据 Frame 保留。原 Collapsed 展示状态改为空内容状态，区域标识不再折叠；用户自输入新增独立状态组件，详见[整合记录](interaction.md)。
- 历史方案中曾将 Goal 独立文字条目列为后续能力；本需求将其纳入待设计的 MVP，不回写或删除历史实施记录。

## 7. 后续实现的验收要求

以下为功能的验收依据。自输入与区域 UI 的实际检查见[实现记录](implementation.md)；本次 Response 实际检查及未执行项见 [Response 实现记录](response-implementation.md)。后续置顶不属于本次实现。

1. 无书籍、无高亮或笔记时，仍可在 Goal 下创建并保存自写内容；重新打开后可读取、编辑和删除。
2. 同一 Goal 中，自写内容与已有高亮、笔记共同呈现，没有独立的 Linked 分组标识；来源仍可识别。
3. Highlight、Note 既有 Link 组件及相关操作可继续使用；移出 Goal 后原标注仍在，原文定位仍有效。
4. 子 Goal 仍可正常进入、改写和继续展开；自写内容不会被当作子 Goal。
5. 三类内容都可以标记或取消 Response；无标签内容同样可创建、关联和保存。
6. 同一材料在两个 Goal 中的 Response 标记互不影响；标记和取消标记在重新打开后保留。
7. Response 不自动完成 Goal，也不自动建立独立分组；MVP 中添加或取消标签不改变内容顺序，实现需保留后续联动置顶的代码可扩展性。
8. 用户可以保留 Goal 并记录回应，也可以直接改写 Goal；两条路径互不强制依赖。
9. MVP 只提供产品定义的 Response，不出现用户自定义标签入口。
10. 统一内容区位于子 Goal 下方；MVP 中新建自写内容或新归入高亮、笔记后，新内容出现在内容区顶部，已有内容保持相对顺序。编辑已有内容不按新增处理。
11. 后续实现联动置顶时，Response 在当前内容区内持续优先，多条按标记时间新者在上；新增普通内容不越过 Response，并满足第 5.4.2 节示例。
12. 模块标识与采用的 02 方案一致：分支图标识别子 Goal 区、叠层文档图标识别内容区，“文档＋”图标表示新增内容；父 Goal 沿用原 Figma 文字样式且没有目标图标，不恢复模块文字标题或贯穿内容的层级导引线。
13. 分支与叠层文档图标不执行动作；新增入口仍可操作。自写内容可以创建多条，每条支持换行，并归属于创建它的 Goal。
14. 新草稿位于已有内容前，空草稿结束时丢弃；已有记录通过原位编辑或明确删除操作处理。保存失败时保留文字，关闭错误反馈不表示保存成功。具体键盘与事件验收以[交互约定](interaction.md)为准。
15. 三类内容都从标签图标进入菜单；界面无 Mark Response 按钮文字，菜单只显示一个 Response 可切换选项；点击入口本身不改变标记。
16. 在左侧空间足够的侧栏和完整工作区中，菜单向入口左侧展开，间距及垂直对齐符合第 5.7 节；边缘避让后仍完整可见。滚动或调整窗口不使菜单脱离目标。
17. 未标记与已标记时的菜单选中状态正确；选择后菜单关闭，浅底和标签随之更新，正文、来源、列表顺序及既有操作保留。关闭菜单且未选择时，标记不变。
18. 鼠标、键盘和无 hover 设备均可完成标记／取消。Escape 关闭、焦点返回、点击外部和连续打开不同条目不会误编辑正文或误操作其他条目。
19. 菜单开闭有平滑过渡，不改变列表布局；系统启用减少动态效果时取消过渡。打开菜单不能被误显示为 Response 已标记。
20. 保存失败保留最新选择并显示可重试反馈；关闭错误提示不确认保存，连续切换标记后的旧结果不能覆盖新选择；在 Goal A 发起操作后切到 B，不会标记 B。
21. 新草稿、正文编辑中和不可编辑状态遵守第 5.6 节入口约定；删除已标记记录后不残留标签空块；同一 Goal 的侧栏、完整工作区和刷新重开结果一致。

Response 操作路径已按第 5.6—5.9 节确定。后续实现时，按项目验证基线执行相关构建、自动检查和真实界面操作验证；本次文档更新不计作上述功能验收通过。
