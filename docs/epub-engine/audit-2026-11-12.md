# AuraReader EPUB 技术审计报告

## 1. 总体结论与验证范围

**当前项目具备基础 EPUB 文本阅读能力，整体属于部分支持。以 EPUB 3.3 Reading Systems 为基线，资源解析、字体、导航、Fixed Layout 等环节存在明确缺口，当前证据不足以建立合规结论。**

实际处理链路为 `AppCoordinator.importBook()` → `parseEpub()` → 保存章节 HTML → `ReaderController.paintChapter()` → 浏览器 CSS 多栏分页或章节内纵向滚动。导入过程中，原书样式、文档外层属性及大部分包信息被丢弃，后续渲染依赖这些转换后的 HTML。[导入入口](/E:/dp/reader_workstation/src/client/app/appCoordinator.ts:167)、[解析入口](/E:/dp/reader_workstation/src/client/infrastructure/epubParser.js:356)、[章节渲染](/E:/dp/reader_workstation/src/client/features/reader/readerController.ts:581)

审计基线采用截至 **2026 年 11 月 12 日**的官方文本。EPUB 3.3 当前正式文本日期为 2026 年 1 月 13 日，Reading Systems 3.3 为 2024 年 10 月 17 日。EPUB 3.4 最新文本为 2026 年 11 月 11 日 Candidate Recommendation Draft，仍处于草案阶段。[EPUB 3.3](https://www.w3.org/TR/epub-33/)、[Reading Systems 3.3](https://www.w3.org/TR/epub-rs-33/)、[EPUB 3.4](https://www.w3.org/TR/epub-34/)

## 4. 已发现的渲染缺陷与兼容性风险

**最严重的问题是导入阶段会破坏正文链接和书内排版。**

- **普通跨章链接会被改写成图片 data URL，已复现。**  
  `processChapterImages()` 使用 `img, image, [*|href]`，会选中普通 `<a href="d.xhtml">`。当目标文件存在时，整份 XHTML 被编码成 `data:image/jpeg;base64,...` 并写回 href，后续章节导航失效。[processChapterImages](/E:/dp/reader_workstation/src/client/infrastructure/epubParser.js:35)

- **原书样式在导入时丢失，已复现。**  
  `display:none`、颜色、版面定位、书内断页及 SVG 样式均被删除。隐藏内容可能显现，插图颜色和复杂版式会改变。原书 CSS 应用属于 RS §6.3 的 SHOULD 要求，引用的 TTF／OTF／WOFF／WOFF2 字体支持属于 MUST 要求，当前字体链路存在缺口。[样式删除](/E:/dp/reader_workstation/src/client/infrastructure/epubParser.js:409)、[RS §6.3](https://www.w3.org/TR/epub-rs-33/#sec-css)

- **Fixed Layout 的必要信息被丢弃，代码确认。**  
  `rendition:layout`、viewport 和 itemref override 没有进入书籍模型，固定版式统一进入流式多栏布局。RS §8.1 的固定版式支持及每个 pre-paginated spine 条目对应一页的要求尚未满足。[解析返回结构](/E:/dp/reader_workstation/src/client/infrastructure/epubParser.js:445)、[布局逻辑](/E:/dp/reader_workstation/src/client/features/reader/chapterColumnView.js:67)、[RS §8.1](https://www.w3.org/TR/epub-rs-33/#sec-fixed-layouts)

- **图片及媒体引用覆盖不足，部分已复现。**  
  图片 URL 带片段时查找失败，`srcset`、`source`、视频 poster、音视频 src、SVG `<use href="icons.svg#id">` 保持未解析状态。WebP 被标记成 JPEG，AVIF／JPEG XL 也落入相同分支。浏览器对错误 MIME 的实际容错尚未验证。[资源处理与 MIME 推断](/E:/dp/reader_workstation/src/client/infrastructure/epubParser.js:40)

- **语言、方向和局部字体语义丢失，部分已复现。**  
  提取 body innerHTML 会丢弃 html／body 上的 `lang`、`xml:lang`、`dir`、class。阅读器再把单一书籍语言赋给整个章节，并通过 `!important` 统一覆盖全部后代字体。这会影响多语言章节、等宽代码、符号字体、RTL 和竖排书。[body 提取](/E:/dp/reader_workstation/src/client/infrastructure/epubParser.js:414)、[applyTypography](/E:/dp/reader_workstation/src/client/features/reader/readerController.ts:511)、[字体覆盖](/E:/dp/reader_workstation/src/client/styles.css:531)

- **正文链接和锚点定位有歧义，已复现部分路径错误。**  
  正文链接解析缺少当前文档基路径，重名文件会退回 basename 并跳错章。锚点最终通过文字片段搜索定位，重复句可能命中更早位置，空锚点和图片锚点也缺少可靠定位。[resolveTargetPage](/E:/dp/reader_workstation/src/client/domain/readingLocation.ts:34)、[placeAnchorIdAtTopLeft](/E:/dp/reader_workstation/src/client/features/reader/chapterColumnView.js:123)、[locateSnippet](/E:/dp/reader_workstation/src/client/features/reader/chapterColumnView.js:280)

- **大图片、宽表格及复杂文本的分页存在风险，尚未视觉验证。**  
  分页容器固定高度并隐藏溢出，缺少阅读正文专用的图片缩放、宽表格和长代码处理。图片 load 只触发可见区域更新，缺少阅读位置保持及重新分页的完整链路。句锚定位还会拆分和复制祖先结构，Ruby、MathML、SVG 等缺少专项保护。[分页容器](/E:/dp/reader_workstation/src/client/features/reader/chapterColumnView.js:70)、[load 监听](/E:/dp/reader_workstation/src/client/features/reader/readerController.ts:465)、[结构拆分](/E:/dp/reader_workstation/src/client/features/reader/chapterColumnView.js:346)

- **书籍内容与应用共享 DOM，脚本清理不完整，代码确认。**  
  事件处理属性、iframe／object 等内容没有统一清理。桌面模式通过 CSP 限制部分执行与资源加载，浏览器模式缺少同等策略。恢复原书 CSS／脚本前，需要建立书籍级文档与资源隔离。浏览器模式事件触发性本次尚未验证。[直接 innerHTML 挂载](/E:/dp/reader_workstation/src/client/features/reader/readerController.ts:584)、[桌面限制](/E:/dp/reader_workstation/src/desktop/assets.cjs:5)、[浏览器入口](/E:/dp/reader_workstation/src/client/index.html:1)

## 6. 按优先级排序的优化建议

| 优先级 | 建议 | 对应收益 |
|---|---|---|
| **P0** | 修复图片处理误选 `<a>`，限制处理到明确的图片资源属性，保留正文 href | 恢复普通跨章导航，避免导入时破坏内容 |
| **P0** | 建立统一的容器 URL 解析与资源访问层，覆盖文档基路径、`./`／`../`、编码、片段和媒体类型 | 同时解决正文、目录、图片、字体、SVG 和媒体路径问题 |
| **P0** | 建立书籍级文档隔离，并保留原始 EPUB 或完整资源及文档信息 | 支撑原书 CSS 恢复、独立命名空间和可靠资源生命周期，减少后续重新导入需求 |
| **P1** | 完整保留 Manifest／Spine 数据，实现 fallback 链、重复引用首次定位、NAV heading、主标题和 UTF-16 解码 | 补齐已复现的 EPUB 3.3 合规缺口 |
| **P1** | 支持原书 CSS、嵌入字体和字体反混淆，保留章节根语言／方向，提供可控的阅读样式覆盖 | 提高普通出版物、代码、公式和国际化内容兼容性 |
| **P1** | 增加 Fixed Layout 独立渲染路径，处理 viewport、包级及条目级布局信息，再完善 RTL／竖排分页轴 | 满足固定版式核心要求，减少绘本、漫画和日文书异常 |
| **P1** | 解析与解压移到专用 Worker，资源去重并按需加载，将书库摘要与正文读取拆开 | 降低首次打开延迟、主线程占用和整库内存成本 |
| **P2** | 增加图片解码与像素预算、资源缓存上限、迟到资源重排和阅读位置恢复 | 稳定大图片书、长章及复杂分页 |
| **P2** | 按产品需要补齐音视频与 Media Overlays，并优化标注索引和可见区域计算 | 扩展富媒体能力，改善重标注场景性能 |

EPUB 3.4 前向兼容应优先考虑 **roll layout、AVIF、JPEG XL、Opus in MP4**，同时保留 EPUB 3.3 的 fallback 处理。3.4 草案已将部分旧特性列为 outdated，历史内容兼容仍需要对应处理。当前章节内滚动与草案要求的跨 spine 无缝 roll 布局之间存在实现缺口。[3.4 变更记录](https://www.w3.org/TR/epub-34/#change-log)、[Reading Systems 3.4](https://www.w3.org/TR/epub-rs-34/)

后续验收可以保持轻量，先选取直接覆盖上述缺陷的 W3C 测试书，记录通过、失败和待验证结果，再对少量代表性书籍测量首屏、翻页和峰值内存。EPUBCheck 用于确认输入书籍的格式质量，阅读器渲染能力仍需通过测试书实际打开验证。当前 EPUBCheck 主仓库已说明其生产版本转向 EPUB 3.4 校验，建立 3.3 基线时应固定工具版本及规则。[W3C epub-tests](https://github.com/w3c/epub-tests)、[EPUBCheck](https://github.com/w3c/epubcheck)
