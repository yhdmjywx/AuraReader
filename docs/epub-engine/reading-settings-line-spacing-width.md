# Reading settings：行距与行宽需求及设计

日期：2026-11-13。工作分支：`codex/epub-engine`。

状态：已完成需求文档、Figma 设计、源码实现及 Web 定向验证；[实施与验证记录](reading-settings-implementation-2026-11-13.md) 列出实现范围和验证边界。Figma 设计交付时点的原始记录见第 7 节。

## 1. 目标与范围

在现有 Reading settings 中增加行距、行宽两个调整项。保持原入口、面板、字体、字号、缩进、纸张和 Scroll / Page 操作；不新建设置模块、不增加应用／原书模式切换，也不增加全局或单书偏好管理。本任务的行宽是正文阅读区域宽度，不是字距；行距不是段距。

以导入后的原书文档和 CSS 为内容基础，只覆盖用户明确调整的排版属性。保留 XHTML 结构、章节标识、原始资源、链接、字体选择和特殊内容语义。设计依据为 [Design System](../design/design-system.md)、[Design Index](../design/design-index.md) 和 [P1 实施记录](p1-implementation-2026-11-12.md)。不修改这些文档已约定的其他模块行为。

## 3. 面板与交互

行顺序：Font → Size → **Line spacing** → **Reading width** → Indent → Paper → Layout。

新增两行复用当前 Size 行的标签、分隔线、左右对齐、按钮尺寸、图标、圆角与中性色。保留现有面板宽度，允许面板随两行增高；受窗口高度限制时使用面板内部滚动，保证所有原控件可达。工具栏和正文不因面板展开而移位。

| 项目 | 行距 | 行宽 |
| --- | --- | --- |
| 英文标签 | Line spacing | Reading width |
| 展示示例 | `−  1.85×  +` | `−  560px  +` |
| 含义 | 无单位的正文行高倍数，随字号缩放 | 正文视口的物理宽度，排除侧栏和页边笔记 |
| 建议调整范围 | 1.20–2.40，步长 0.05 | 首选宽度 320–800px，步长 40px |
| 初次显示 | 读取当前正文代表段落的计算行高／字号；无法取得数值时回退应用基础 1.85。混合行距仅显示代表正文值，不声称全书一致 | 显示当前布局实际可用的正文宽度，现有首选值为 560px |
| 生效时机 | 第一次点击后建立行距覆盖；仅打开菜单不建立覆盖 | 点击后更新首选宽度，并经过现有空间约束得到有效宽度 |
| 边界 | 到达范围边界时对应按钮禁用；原书值超出范围时先如实显示，首次操作进入相应边界 | 空间不足时实际宽度可小于 320px；保留首选值供窗口变宽后恢复。无可用增宽空间时禁用加号 |

行宽数值显示有效宽度，避免显示 800px 而正文实际只有 500px。被空间约束时通过 tooltip／可访问说明交代首选值和当前可用值，不增加常驻说明行。宽度计算继续使用原有笔记宽度、间隔和可用空间规则；不在本任务中更改笔记布局策略。

宽度按钮以当前有效宽度为操作起点，再将结果写入首选宽度并限制到可调整范围。例如首选 560px、实际 448px 时，减号应立即缩到 408px，不能先把首选改成 520px 却让正文保持不变。小窗口实际值低于 320px 时禁用减号；可增宽时的首次加号进入允许范围，再按步长调整。

两个控件都是普通步进控件，不加入各自的“原书”选项，不加确认、保存或重置按钮。点击后面板保持打开并立即预览。沿用菜单的 Escape、外部点击关闭和焦点管理；Tab 可达按钮，Enter / Space 激活，禁用态同时具备语义和视觉反馈。按钮可访问名称分别为 Increase / Decrease line spacing、Increase / Decrease reading width。

本阶段不规定新的跨书／跨会话持久化策略，不引入偏好数据库或优先级系统。后续实施先沿用现有 ReaderController 生命周期；若需要扩展存储作用域，另行确认。

## 4. 可控覆盖与特殊内容

- 行距只覆盖普通正文段落、列表正文、引用等适用内容的行高。标题保留原书层级和比例，不全局对所有后代设置同一 `line-height !important`；不清空或重写整份出版物 CSS。
- 代码、公式、MathML、Ruby、SVG、表格和媒体保留内部排版。外层普通文字可参与正文重排；代码行距、公式内部尺寸、Ruby 标注关系不因统一选择器被覆盖。溢出问题不能通过裁切内容或重写源 XHTML 解决。
- 竖排、RTL 保留原书 writing-mode / direction。行距按浏览器相应排版方向生效；行宽表示物理阅读区域，不借此改变阅读方向、强制横排或交换翻页方向。
- Fixed Layout 的两项控件禁用，使用可访问说明解释其保留原书页面布局；继续沿用既有整页适配。不得改变原书 viewport、固定坐标或逐元素重排。混合版式书籍按当前章节判断可用性，返回流式章节后恢复该会话的有效调整。
- 字体、字号、缩进、主题、链接、脚注、图片适配与迟到资源重排沿用现有功能。本任务不增加其他覆盖开关。

## 5. 分页、阅读位置与业务关联

每次有效调整按“记住原文定位 → 更新排版参数 → 测量当前章节 → 恢复原文位置 → 重绘标注和页边笔记”执行，复用现有读取、锚点和布局入口。连续快速点击应合并可合并的布局测量，最终值必须生效；不反复解压或重新导入书籍。

沿用现有页数含义：源章节／源页标识保持稳定；屏幕页数来自当前视口及实际布局。Page 模式同步更新总屏数、当前位置和翻页步长；Scroll 模式按现有逻辑更新位置，清除分页残留位移。不新增另一套全书估算页数、额外分页栏或底部页码。

调整前后的定位应以稳定章节标识及原文文本位置为依据，不能只恢复屏幕页号。调整后当前阅读文本应继续可见；高亮、笔记、Goal 关联、目录、跨章链接、导出和恢复的源坐标不改写。页边笔记继续使用原有数据与统一几何重新定位，DOM 和 Range 保留在 reader 边界。

图片页按有效内容区域重新适配，不回退到已修复的根容器高度／栏偏移计算。窗口缩放、字体加载、图片迟到引起的重排也必须使用当前行距和有效行宽。

## 6. 设计状态与后续验收

Figma 应覆盖：正常两行、按钮 hover / focus / pressed、行距上下限、行宽受限、固定版式禁用、小高度面板溢出。优先使用原组件和现有实例表达，状态参考只用于这两项设计，不建立新的产品设置模块。

后续实施的必要验收范围：

1. 普通流式 EPUB 在 Page / Scroll 中分别调整两项，显示值与正文一致，首次打开菜单不改变原书；窄窗口和侧栏变化无横向越界或笔记重叠。
2. 调整前后当前原文可定位；前后翻页和章节首尾无漏页／重复页；纯图片页可完整显示，原分页工具栏唯一。
3. 高亮和笔记链接仍定位原文，页边笔记跟随重排；原有 Font、Size、Indent、Paper、Layout 交互保持可用。
4. 定向样书检查代码／公式／Ruby、RTL／竖排和固定版式保护边界；不扩展成完整标准测试矩阵。
5. 原要求在 ChatGPT 内置浏览器进行应用功能测试；实现阶段该接口不可用，用户于 2026-11-13 明确授权改用 ego 浏览器测试网页版。仍不进行桌面版测试；执行项目构建和针对性检查。

设计阶段只验证文档和实际完成的 Figma 设计，不将静态设计、截图或原有测试记录写成新增功能通过测试。后续源码及真实交互结果另见实施记录。
