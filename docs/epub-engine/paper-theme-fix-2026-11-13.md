# Paper 换色裁切：修复与 Web 验证

日期：2026-11-13。分支：`codex/epub-engine`。本轮只修复 Paper 换色引起的容器边框污染及相关高亮背景丢失，保留当前分页算法、主题同步路径和业务数据结构。

## 1. 原因与实现

原 `.paper-white`／`.paper-sepia`／`.paper-dark` 同时定义背景和 1px 边框。Paper 点击后，类名被应用到 reader panel，并通过现有主题同步复制到阅读 iframe 的 html。装饰边框占用了分页根的内容尺寸，但列宽及翻页步长仍按原尺寸计算，导致列起点累积偏移、右侧残字或裁切。

调查时在实书中记录到，560px 的列步长对应实际约 558.48px 的列间距；iframe 高度同时减少约 2px。该记录与修复验收使用的窗口高度不同，只用于说明原缺陷，不跨窗口直接比较高度。

另一个直接相关问题是主题规则对正文所有后代统一设置 `background-color:transparent!important`，使原有 `.annotation-token` 高亮背景消失，标注数据本身仍然存在。

本轮源代码仅修改两处：

- `src/client/styles.css` 的 Paper 样式：保留既有背景色，把边框限定到 `.paper-btn.paper-*`；容器和 iframe 根不再获得色块装饰边框。
- `src/client/features/reader/publicationDocument.ts` 的阅读主题覆盖：拆开文字颜色和背景覆盖。背景清理避开 `.annotation-token` 及其后代、语义 `<mark>` 及其后代；`<mark>` 同时避开文字颜色强制继承，保留原来的前景与背景搭配。原有 SVG／图片／视频及 Fixed Layout 排除条件继续保留。

没有改动分页、翻页、定位、选区控制器、标注存储、Goal、解析、备份或导出逻辑；未新增依赖。用户书籍不需要重新导入。

## 4. 上下白条的补充修复

用户随后确认“原书内容＋可控覆盖”的 Paper 方向，并要求先解决上下白条。该问题与第 1 节的边框尺寸污染不同：Readium CSS 仍将 iframe 的 html 根背景设为白色，而外层面板及 body 已切换为所选颜色。分页上 28px／下 32px 留白位于 html 上，因此露出白条。前一轮尺寸回归没有覆盖留白区域颜色，不能据其通过推断视觉已经完整正确。

本次仅在 `publicationDocument.ts` 的 adapter 中增加一条根背景规则：有 `data-user-paper` 且直接子 body 是非固定版式的 `.book-paper` 时，html 使用 `--bg-paper` 作为 `background-color`。只补背景颜色，不改 padding、宽高、列宽、滚动位置或背景图片属性；没有修改原来的正文颜色处理、局部样式策略、Paper 控件、字体或分页算法。

已接受的后续 Paper 规则仍是：原书样式为基础，用户明确操作后应用覆盖；普通正文使用主题配色，标题／链接／强调色与独立底色区域需要限定保护，独立区域的前景与背景成对保留；保护图片、SVG、背景图片、标注和 Fixed Layout 页面内容；选中状态与实际覆盖一致，切章保持有效状态。这些完整规则尚未全部实施，本次不把根背景修复报告为完整 Paper 方案或预设系统交付。
