# AuraReader + Goal：围绕读者实际体验的市场调研

调研日期：2026-10-25。独立重做，未读取或沿用此前市场调研文件。

## 结论

有相似产品，而且竞争相当具体。AuraReader + Goal 进入的是“阅读过程中形成自己的理解，并保留可再次使用的阅读成果”的市场。MarginNote、LiquidText、Readwise Reader 是值得优先比较的三个成熟商业对手；Zotero + Better Notes 是非常重要的免费替代；Heptabase 和 RemNote 竞争的是用户整理理解、学习和研究的时间与预算。

最有希望的切入点是：**在 Windows 上读自己已有的 EPUB 时，让自己的问题、眼前的原文和自己的判断同时在场，并把阅读成果完整带走。**

这是一项具体的组合体验机会，不是无人做过的功能发明。目标树、摘录归类、原文跳转、自由笔记、离线使用、Markdown 导出，分别都存在成熟替代。尚未找到在本次核查范围内，以你描述的整套交互为默认路径的完全同款；这不等于全市场不存在，也不等于竞品无法实现。

**无法可靠给出“同类产品用户最多的前三名”。** 主流产品未公开同一时期、同一口径的活跃人数。下面提供规模证据和三个重点对标对象，明确不把它们伪装成用户量榜单。

## 1. 调研依据和边界

本项目依据：当前 README、笔记渲染与编辑源码、可见标注筛选、章节导出实现、会话代码、Goal 原型和实现说明，以及项目内阅读／导出截图。发生冲突时，以当前实现和本轮用户给出的 Goal 设计为准；没有修改业务代码。

竞品依据：官方网站、使用文档、价格页、应用商店、官方开源仓库，以及少量公开用户反馈。竞品流程是依据这些材料重建的操作路径，**不是本次逐个购买、登录实测所得**。本项目也没有在本次调研中做新的用户可用性实验。不能据此声称“快 30%”“少五次点击”或“用户一定愿意买”。

证据分三层：

- **已确认事实**：源码或一手文档明确支持。
- **体验推断**：根据用户需要完成的动作、切换的界面和组织对象推导。
- **商业假设**：需要试用、留存、真实购买进一步验证。

价格为调研时页面展示，币种 USD，地区、税费和渠道可能不同。论坛个案用于识别需求，不代表整个用户群，也不将历史抱怨当成当前版本仍有的缺陷。

## 2. 我们现在到底提供什么体验

| 阅读时刻 | 当前已实现 | 加上本轮 Goal 设计后的整体体验 | 不能提前宣称的部分 |
| --- | --- | --- | --- |
| 打开书 | Windows Electron 候选版；本地 EPUB/TXT 导入，书库和目录 | 读者可在没有任何摘录时先写“我为什么读” | Goal 尚未接入正式业务与持久化 |
| 持续阅读 | 单页、双页、滚动；字体和背景调整 | 单页正文左边呈现当前 Goal，右边保留页边笔记 | 双页 Goal 和小窗口体验尚未解决 |
| 看见一句有感触的话 | 选文高亮、写笔记；笔记在正文附近显示 | 读者主动将某条高亮／笔记归入左侧选中的 Goal | 不能把所有新标注自动解释为服务于当前目的 |
| 改变想法 | 点击笔记直接原位编辑 | 可以改写 Goal、展开子问题，不设置完成率或标准答案 | 不等于已提供思考历史／版本演变记录 |
| 产生无选区的想法 | 当前普通笔记主要依赖原文引用 | Goal 可容纳直接输入的解释、疑问和判断 | Goal 自由文字属于后续希望加入的能力 |
| 回看一个问题 | 当前页边笔记随可见原文变化 | 切换 Goal 或新归入内容后自动显示已有内容，点击回原文 | 跨书 Goal 未由本轮设计明确；不能当现成功能 |
| 表达态度 | 高亮与笔记 | 后续在 Goal 语境中显式表达赞成／反对等态度 | 点赞点踩的对象、含义与位置尚未确定 |
| 带走成果 | 章节 Markdown 保留正文、高亮和段后笔记；每书备份 | 可以进一步形成“目的—子问题—自己的文字—引用”的可迁移成果 | 现有 Markdown 导出不等于已能导出完整 Goal 结构 |

源码核查发现几个非常关键的细节：

1. 页边笔记不是普通的全书笔记列表。它按实际可见的原文片段筛选；跨页引用仍部分可见时保留。这意味着它服务于“此刻读这一段”，而 Goal 服务于“跨段落持续想这个问题”。两者互补，不能让左侧变成另一个重复的笔记栏。
2. 沉浸式页边只呈现读者自己的文字，引用保留在数据与导出里。减少重复引用，是正文仍占主体的实际原因之一。
3. 编辑保留原来的输入框、光标和中文输入状态。对需要写长一点判断的人，这类稳定性比再增加一种知识关系更影响日常体验。
4. 导出支持“当前／全部／自选章节”，多章带目录概览；不是仅把高亮句子抽成清单。
5. README 仍有旧 HTML 导出描述，但当前导出控制器以章节 Markdown、笔记摘要和备份为主，不能把残留文案算成新的卖点。

项目证据：[README](../README.md)、[页边笔记与原位编辑](../src/client/features/annotations/notesUI.js)、[可见片段筛选](../src/client/features/reader/visibleAnnotations.js)、[章节导出](../src/client/infrastructure/exporters.js)、[Goal 原型](prototypes/goals.html)。

微信读书、Kindle 等大众阅读平台也争夺阅读时间，但若只用它们做对比，会高估我们的独特性。用户选择大众平台还涉及书源、购买、设备和移动习惯，本项目当前是导入自有文件的桌面工具。Obsidian／Notion 也可以承载问题和摘录，但更适合作为用户已有的后续整理环境来看待。

一个容易遗漏的历史参照是 SuperMemo 的增量阅读：把文章片段继续提取、展开、转换成问答已有长期实践。Goal 的区别在于目的可以是体验、怀疑和理解，不必须转成记忆题或进入调度算法。因此“带着问题读”不是新概念，值得争取的是它在日常 EPUB 阅读中的低负担实现。[SuperMemo 官方增量阅读说明](https://super-memory.org/archive/help/read.htm)

## 4. “用户最多的前三名”：能确认什么

| 产品 | 可核查的公开证据 | 数据范围 | 能得出的结论 |

| LiquidText | 官网公司页列出约 600 万下载、20,000+ 月度法律用户 | 下载为累计口径；法律用户仅一个细分人群 | 已有明显商业采用，不能当成 600 万活跃用户 |

| MarginNote | 官网展示 MN3 5,000+ 评论、MN4 665 评论等商店反馈指标 | 评论，不是独立用户数；版本和地区影响统计 | 有长期用户基础，但不足以排用户人数名次 |

来源：[LiquidText 公司数据](https://law.liquidtext.net/company/)、[Reader Google Play](https://play.google.com/store/apps/details?id=com.readermobile)、[MarginNote 官网展示](https://www.marginnote.com/en/index.html)。这些是页面在调研日可访问的声明，不是第三方审计数据。

**不能把“600 万下载、10 万 Android 下载、5 千条评论”按大小排序。** 本次没有获得 MarginNote、Reader、Zotero、Heptabase 等同口径的当前全平台活跃人数，所以“用户最多前三”这一问题仍然没有可证实的答案。

下面选择 MarginNote、LiquidText、Readwise Reader 做三项重点商业对标，理由是它们分别覆盖结构化深读、材料分析、阅读流转，且有可检查的产品与商业采用证据。**这个选择是竞争相关性判断，不是人数前三。** Zotero 也不能因为免费、缺同口径人数而被排除竞争分析。

## 5. 三个重点商业对手：放进同一个阅读场景比较

统一场景：读者打开一本书，先写“为什么我不认同作者对自由的解释”；在两个章节找到相关材料，写下自己的判断；发现子问题“选择多是否就意味着自由”；隔几天回来继续，最后把成果带到已有笔记库。

### 5.1 MarginNote：最接近 Goal 树的结构替代

官方当前产品围绕原文摘录、卡片、导图与复习组织。用户可以用节点标题表达自己的问题，把相关摘录组织在其下面，并利用来源链接返回文档。**因此，父问题、子问题、摘录聚合和来源追溯，本身都不能作为我们独占的能力。**

重建上述任务时，MarginNote 用户主要在阅读材料和卡片结构之间工作；AuraReader 的设计则把当前问题放在正文旁，用选中目标后的归入动作维持一条阅读线索。差异是常驻视觉对象与组织负担，不是别人不能提问题。MarginNote 也有沉浸模式，不能概括成“它一定复杂、我们一定简洁”。[MarginNote 产品说明](https://www.marginnote.com/en/index.html)

对希望最后得到系统大纲或复习卡片的人，MarginNote 的结构是收益。对只想把一个疑问带着往下读、不愿维护导图的人，我们可能更贴合。是否更贴合，需比较实际连续阅读，而不是对比界面截图的空白面积。

平台是当前明确的差异：MarginNote 的官方购买渠道覆盖 Apple 设备；我们的候选桌面版本面向 Windows。价格也并不普遍昂贵：官方美元页列出 iPhone/iPad Pro $12.99 买断、Max $16.99/年或 $51.99 买断，Mac DMG Standard $35，Premium 升级包另加 $10。不能用“比高价订阅便宜”概括整个市场。[MarginNote 定价及平台范围](https://www.marginnote.com/en/pricing/index.html)

**竞争判断：** 如果用户说“我已经习惯 MarginNote，用问题作为节点就可以”，Goal 的命名不足以促使迁移。必须展示正文、问题和自己的话如何在更少的整理操作下连续工作。

### 5.2 LiquidText：最接近“阅读中保留自己的分析”

LiquidText 的项目把文档区与可放置摘录、自由文字及关系的工作区结合。用户可先写一个疑问，再把材料放在附近，连接并返回来源，也能跨页、跨文档分析。它已有 Windows 版本，不能把“电脑上边读边思考”当成我们独有。[LiquidText 工作流](https://www.liquidtext.net/liquidtextadeeperdive)

在同一任务中，LiquidText 更适合把几处证据拿出来并置、连接和比较；AuraReader 更适合在连续读一本重排 EPUB 时，用轻量的当前 Goal 保留关注方向。前者的工作区能成为正式分析产物；后者希望正文始终占主导。

LiquidText 支持把结果导出 PDF、DOCX，并提供同步服务；“他们导不出成果”“必须自己拼资料”都不成立。它的多材料分析和协作能力也不是我们当前拥有的。[LiquidText 平台、导出和同步](https://www.liquidtext.net/)

**竞争判断：** 律师、研究人员如果必须处理扫描 PDF、比较很多材料、手写或团队协作，当前 AuraReader 难以替代。更现实的切入对象是阅读自有 EPUB、重视连续阅读的人。本次未获得可直接确认的官方完整价格表，不采用互相冲突的第三方报价来给它定价。

### 5.3 Readwise Reader：最强的“为什么我要换一个阅读入口”对手

Reader 支持文档标签与高亮标签，用户可以用标签组织材料，也有文档笔记。用它完成示例任务时，可以先记下问题，再给相关高亮加标签，必要时到笔记工具继续展开。这条路径已经能完成目的性阅读的一部分；不足之处不能直接表述成“它只能收藏”。[Reader 组织内容说明](https://docs.readwise.io/reader/docs/organizing-content)、[Reader API 中的文档／高亮笔记](https://readwise.io/reader_api)

AuraReader 的潜在区别是：这个目的本身成为持续存在、可以展开和直接写入的阅读对象，切换后马上看见围绕它积累的内容。用户不用把一个标签、一个文档笔记和外部笔记库中的小标题自行约定为同一件事。这是设计推断，不能说 Reader 完全没有替代路径。

特别需要纠正对导出的误判：Reader 已可导出笔记高亮为 Markdown、导出完整文件／文章，并在 Web 端打印带标注正文。**我们的可比较点是按 EPUB 章节把正文、高亮、段后笔记组织成可继续编辑的 Markdown，而不是泛泛的“我们能带走原文，他们只能带走摘录”。** 本次文档未证明 Reader 提供完全相同的章节内嵌 Markdown 布局，但也未逐格式实测其所有导出路径。[Reader 导出文档](https://docs.readwise.io/reader/docs/faqs/exporting)

Reader 官方价格为年付折合 $9.99/月（$119.88/年），月付 $12.99，含 Readwise；它同时销售阅读、回顾、导出集成等整套价值。它能离线工作，所以“无网能读”不构成对它的独占优势；我们的区别是本地独立书库、当前没有账户与云服务依赖。[定价](https://readwise.io/pricing/reader)、[离线能力](https://docs.readwise.io/reader/docs/faqs)

**竞争判断：** 如果用户依赖 RSS、网页、手机和笔记工具自动同步，我们无法只靠 Goal 促使其全面迁移。更可能成为他在 PC 精读某些书时使用的补充工具，因此导出与已有知识库的衔接非常重要。

## 6. 不能遗漏的强替代：Zotero、Heptabase、RemNote

**Zotero + Better Notes：最应认真面对的免费组合。** Zotero 允许在阅读器中创建或打开自己的笔记，将选中的标注加入笔记，并保留返回原文的链接及引用。用户完全可以先写问题标题，再在下面组织自己的解释和证据。Better Notes 提供大纲、笔记链接、模板、Markdown 同步和多格式导出。[Zotero 官方说明](https://www.zotero.org/support/pdf_reader)、[Better Notes 仓库](https://github.com/windingwind/zotero-better-notes)

我们的机会是省去把研究管理工具配置成个人阅读环境的准备，以及让笔记紧贴当前可见正文的界面体验。但对已经配置好这个组合的用户，配置成本已经付过；他不会仅因为我们“更轻”就迁移。若他需要规范引用、多材料组织，Zotero 的额外能力反而更重要。

**Heptabase：目的和理解不是我们的独占定位。** 它本来就强调围绕学习主题和研究项目组织理解。它的白板能承载问题、摘录和自己的解释。当前官方帮助页明确说尚不原生支持 EPUB，需要转换为 PDF 或文本，因此 EPUB 连续阅读是此刻具体可比较的差异；这不是永久壁垒。官方 Pro 年付页面显示折合 $8.99/月。[产品](https://heptabase.com/)、[书籍格式边界](https://support.heptabase.com/en/articles/16762580-how-do-i-use-a-whole-book-or-long-pdf-with-heptabase-ai)、[定价](https://heptabase.com/pricing)

**RemNote：界面和层级笔记也可能非常接近。** 其阅读器支持中间正文、旁边自己的笔记；Notes pane 可置于左或右，并能把高亮与笔记／闪卡关联。这里已经存在“正文旁写层级文字”的实现，不能把三列位置关系本身当成新发明。差异在于我们不要求把阅读成果转换为学习卡、记忆调度或 AI 辅导；RemNote 的文档阅读以 PDF 及转为 PDF 的材料为主。[RemNote 当前官方教程](https://help.remnote.com/en/articles/6690975-learning-from-pdfs-and-files-with-the-remnote-reader)

## 7. 从真实用户反馈看需求，而不是用功能表推测所有人

| 公开反馈 | 它支持的需求判断 | 它不能证明什么 |
| --- | --- | --- |
| Reader 一位长期付费用户表示，自己投入大量时间配置标签、视图和订阅源，但未读内容膨胀，实际使用减少；创始人回复并随后提到已推出改善 | 收集更多并不必然让人读得更好；用户可能为减少管理负担寻找替代 | 不能说 Reader 当前仍普遍卡顿，也不能说用户都不需要 RSS |
| MarginNote 官网转载用户实践：阅读时先快速记，再做综合整理 | 阅读中的捕捉和之后的理解组织是两种不同任务 | 不能据此认定第二阶段一定多余，或认为我们的 Goal 会消灭整理 |
| Heptabase 创始人在社区信中承认部分用户对 AI 按钮干扰、价格和非 AI 功能优先级有顾虑，并提出改进 | 有人希望核心阅读／思考体验受到保护，“默认自己思考”有实际需求信号 | 不能推出用户总体反 AI，也不能将竞品视为不能关闭 AI 或不再重视手工体验 |

来源：[Reader 原帖与官方跟进](https://www.reddit.com/r/readwise/comments/1mj9gh6/longtime_user_of_reader_but_im_considering/)、[MarginNote 官网用户实践](https://www.marginnote.com/en/index.html)、[Heptabase 社区信](https://www.reddit.com/r/heptabase/comments/1vliyvi/heptabase_community_letter_ama/)。第二项是厂商挑选转载的案例，原论坛页本次未能访问，证据强度低于直接访谈。

这几类反馈合在一起，支持一个更窄的假设：**有一部分深读用户想保存阅读中的理解，却不愿为此维护越来越大的信息系统。** 它们没有给出这个人群的市场规模，更没有证明他愿意为 Goal 付费。

## 8. 我们能做什么他们做不了的？

严格回答：没有证据支持“某个核心思想别人技术上做不了”。应区分当前缺口、默认体验和未来可能的壁垒。

| 具体能力 | 判断 | 对外应如何表达 |
| --- | --- | --- |
| Windows 上使用当前设计的 EPUB + Goal | 相对 MarginNote 是平台差异；对 LiquidText、Reader、Zotero 不是 | “面向 Windows 的目的性 EPUB 阅读体验” |
| 直接打开 EPUB 连续阅读 | 相对当前 Heptabase 官方格式边界有差异；其他阅读器大量已有 | “不用为了整理理解先把 EPUB 转成 PDF” |
| 没有摘录也能建立阅读目的 | 普通笔记、空白节点可模拟；并非逻辑上独占 | “开始阅读时，就可以写下自己的问题” |
| 在正文旁只呈现当前目的、必要父级和子问题 | 有望形成更低的视觉和导航负担，但需实际测试 | “阅读中始终看得见当前在想什么” |
| 先选 Goal，再在原操作处归入；立即看到结果 | 是完整交互路径的差异；尚未实证其更快 | “把这段话留给正在思考的问题” |
| 正文、原位高亮、页边判断、章节 Markdown | 相对部分摘录导出流程有组合优势；Reader 已有其他完整导出路径 | “把原文和你的批注一起带走” |
| 明确区分注意、认同与反对 | 用户可以在竞品写文字表达；点赞点踩也很容易复制 | 等态度语义确定后再展示，暂不作为主卖点 |
| 不使用 AI、本地独立书库 | 有人重视；开源阅读器和其他本地工具同样能满足部分要求 | “你决定目的与关联，书与笔记保存在本机” |

真正比较难复制的不是 Goal 这个对象，而是持续把选文、编辑、关联、跳回原文、恢复阅读和导出做顺。大公司也能开发类似功能，但未必优先服务这群非常具体的用户。这是定位机会，尚不是已建立的护城河。

还有一个设计边界：Goal 文字可以调整，但如果直接覆盖旧文字，就只保留“现在的问题”，不会自动保留“为什么改变了想法”。因此在没有演变记录前，文案应说“积累自己的阅读线索”，避免承诺“完整记录思想如何演变”。

## 9. 卖点、愿意购买的理由，以及阻碍购买的地方

### 9.1 哪些人最值得先服务

| 人群 | 具体场景与痛点 | 可能愿意购买的结果 | 当前匹配程度 |
| --- | --- | --- | --- |
| 经常在 Windows 精读非虚构书的个人读者 | 一本书跨几次阅读，忘了上次为什么划这句 | 回到原来的问题和自己的判断，继续读下去 | 最值得优先验证 |
| 用 Obsidian 等工具写文章、课程或读书札记的人 | 阅读器中有原文，笔记库里只有孤立摘录，之后重新找上下文 | 少搬运、少重建上下文，把材料连同判断带走 | 较强，但需要 Goal 导出形成闭环 |
| 哲学、历史、社会科学等兴趣读者 | 没有标准答案，希望保留疑问、不认同和感受 | 留下一条属于自己的理解线索 | 匹配，但支付意愿未必高 |
| 论文、法律和专业材料研究者 | 要处理 PDF、跨文档证据、规范引用 | 可靠研究工作流 | 当前格式和功能不匹配，暂不宜主攻 |
| 考试用户 | 需要记住内容、练习和复习调度 | 更高效通过考试 | RemNote／MarginNote 更直接 |
| 手机泛读与休闲小说用户 | 需要随时打开、有书源、跨端同步 | 便利与内容获取 | 当前不匹配；Goal 可能成负担 |

Goal 应允许“我想放松”这样的目的，但允许这种表达，不等于应该把放松阅读人群作为最先付费的主市场。不同目的可以在产品中共存，商业切入点可以更集中。

### 9.2 用户购买的不是一棵树

卖点按用户结果排序：

1. **隔几天回来，我能接着自己的问题读。** Goal 聚合判断和材料，降低重建阅读上下文的成本。前提是恢复书籍、位置和 Goal 状态可靠。
2. **我的话就在原文旁边。** 看到作者说了什么，也同时看到自己当时怎么想；不必每次打开一个笔记窗口找。
3. **读完不再面对一堆不知道为什么保存的划线。** 主动关联让摘录保有读者赋予的用途。注意，这也增加了一个动作，必须让回看收益超过整理成本。
4. **读书成果可以直接进入已有工作流。** 章节正文和批注可迁移；若以后连 Goal 的问题结构、自由文字和引用关系一并导出，付费理由更完整。
5. **不用先学一套知识管理方法。** 无模板分类、无完成率、无必需的画布整理，直接写下自己的关注点。此项须通过首次使用测试证实。

可测试的主文案：

> 带着自己的问题读下去。把原文、批注和逐步形成的理解留在一起。

产品解释：

> 在 Windows 上阅读你的 EPUB：正文旁写下自己的话，用 Goal 串起关注的问题，再把阅读成果带到自己的笔记库。

避免把“无 AI”放在唯一的主标题里。它是控制感与专注的支撑条件，不会自动产生用户价值；未来接入 AI 也不应破坏当前读者决定目的与关联的原则。

### 9.3 现有体验中会直接阻止付费的缺口

- **重开不能自动恢复上次书籍和位置。** 当前 README 明确列为限制。这与“继续自己的阅读线索”有直接冲突，优先级高于新增点赞点踩。
- **Goal 还未形成正式持久化、备份与导出闭环。** 内存原型能证明交互方向，不能证明长期投入自己的理解是安全的。
- **支持范围比入口暗示的窄。** PDF 解析未实现，文件选择器／书库文案却可能包含 PDF；首次导入失败会抵消 Goal 的吸引力。
- **目的区依赖屏幕空间。** 单页左侧方案不能默认推广到小笔记本、系统缩放或双页。省掉画布如果换来拥挤的三栏，也不会让体验更轻。
- **没有移动和同步能力。** 可以定位 PC 深读，但不能期待替代用户所有阅读场景。
- **候选安装包未签名，复杂 EPUB 与发布验收仍有边界。** 这影响安装信任和稳定体验，不是营销措辞可以解决的问题。

这些不是建议立刻扩成大型产品；它们是让现有定位成立的基本条件。本次只做调研，没有实施上述修改。

### 9.4 如何判断有人愿意买

竞品已有收费说明市场愿意为学习、分析和阅读流转付费，但不能外推为愿意为我们的具体组合付费。尤其免费 Zotero、Readest 等会压低“普通阅读与标注”的可收费空间。

较合适的商业假设是低门槛的桌面付费版本／便利分发和持续维护价值，或者一次购买一个主要版本，再对明确的新版本收费。当前没有云同步与持续服务，不宜只依据 Reader 的价格套用相近年费。

如需要早期价格实验，可对不同招募批次分别测试人民币 99／199／299 元的单次购买意愿；这仅是测试报价，不是调研得到的市场价格、成本测算或收入预测。项目目前为 Apache-2.0 开源，商业化还必须回答：用户为何为官方版本的安装、稳定性和支持付费，而不是源码本身。

建议只验证四件事：

1. 让已有精读习惯的 8–12 人拿自己的书连续使用两周，包含已经在用 MarginNote、Reader 或 Zotero 的人；不要求他们每章都建立 Goal。
2. 观察他们是否自然创建和修改目的，是否愿意主动关联，切换 Goal 后是否真的找到了想要的材料。
3. 隔几天要求继续先前的问题，比较其原工具和 AuraReader 找回上下文的过程；同时记录误归入和不必要的导航，而不只记录点击速度。
4. 以一次真实导出／写作任务和明确报价结束，区分“喜欢概念”“愿意长期用”“愿意现在购买”。

值得警惕的结果：用户很喜欢演示，却只创建一次 Goal；所有材料都扔进一个根节点；不回看关联内容；每次阅读仍回到原工具。这会说明 Goal 还没有产生足以抵消维护成本的收益。

## 10. 开源项目与它们的意义

| 项目 | 公开许可／范围 | 与本项目有关的体验 | 应如何看待 |
| --- | --- | --- | --- |
| [Readest](https://github.com/readest/readest) | AGPL-3.0-or-later | 跨平台、多格式、标注、并排阅读和查词 | 最值得对标普通 EPUB 阅读的完整度；“舒服、开源、跨平台”已有竞争者 |
| [Koodo Reader](https://github.com/koodo-reader/koodo-reader) | 仓库标示 AGPL-3.0 | 电子书管理、跨设备、标注及外部笔记集成 | “阅读成果可进入其他工具”也不是空白领域 |
| [Zotero](https://github.com/zotero/zotero) + [Better Notes](https://github.com/windingwind/zotero-better-notes) | Zotero 开源，具体许可见仓库 LICENSE；Better Notes 标示 AGPL-3.0 | 阅读、标注、引用、主题笔记；插件提供 Markdown 同步等 | 对 Goal 聚合与导出价值最有挑战性的免费组合 |
| [KOReader](https://github.com/koreader/koreader) | AGPL-3.0 | 面向电纸书，也支持 Android/Linux；多格式与深度阅读设置 | 证明离线和本地控制并不独有；使用设备与我们不同 |
| [Foliate](https://github.com/johnfactotum/foliate) | GPL-3.0-or-later | 面向 Linux 的电子书阅读体验 | 适合参考正文主导的界面；并非 Windows 同平台替代 |
| [Logseq](https://github.com/logseq/logseq) | AGPL-3.0 | 层级块、引用与知识组织 | 可用层级笔记模拟问题结构，但不能因此当作相同 EPUB 阅读体验 |

这份表用于识别替代品与参考对象，不是代码复用许可结论；各项目收费服务、移动端和仓库代码的范围不能一概而论。没有用 GitHub 星数当用户量，也没有因为代码公开就假设所有服务免费。

从产品调研投入看，优先深入 Readest、Zotero + Better Notes、Koodo Reader 三者即可：分别检验我们的基础阅读体验、目的组织价值和成果流转价值是否真的值得用户更换工具。

## 11. 最终判断

这个项目有明确相似产品，存在可切入的细分需求；当前证据不足以证明商业成功或排出真实用户人数前三。

最有价值的整体不是“阅读器加一棵 Goal 树”，而是“正文、此刻的笔记、持续的问题、可带走的成果”之间少打断、少重建的连接。**Goal 必须让人在下一次阅读、下一次回看、下一次写作时拿回收益，才会从一种好看的组织方式变成购买理由。**

现阶段更可信的定位是：为在 Windows 上精读自有 EPUB、重视个人判断且已有成果去向的人，提供一套目的明确、正文主导的阅读体验。不要提前承担跨平台万能阅读器、学术文献管理器或 AI 研究平台的承诺。
