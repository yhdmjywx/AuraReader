# 统一首页与导航：改动计划

日期：2026-10-28。状态：源码已实施、自动回归通过；完整桌面验收尚未完成。以下保留设计约定，实际交付与验收边界见[实施及验证记录](../verification/home-navigation-verification-2026-10-28.md)。

## 目标与边界

书库可用后，每次启动或刷新都进入现有 Goal／选书首页，由用户决定从哪里开始阅读。Goal 可选，建立 Goal、添加书籍关系与打开正文仍是不同操作。

复用现有首页、阅读页、Goal 全页和阅读中紧凑书库。本批处理它们之间的导航、启动与相关异常；双页下线、跨重启进度恢复、完整备份、全面 TypeScript 迁移另行安排。

“继续阅读”本批仅指回到**本次会话中已经打开的书与位置**，返回时不重新调用开书流程。冷启动未加载书籍时不显示该按钮，不承诺跨重启续读。

## 行为约定

| 触发 | 目标行为 |
| --- | --- |
| 桌面首次运行、尚未建库 | 先显示独立的建库界面；创建成功后进入首页，不自动安装示例书 |
| 已建库启动／浏览器刷新 | 无论有无书籍、Goal，都进入首页；不预加载某本书到阅读会话 |
| 首页空库 | 保留“创建 Goal”“导入书籍”两个起点；有 Goal 无书时仍能浏览与编辑 Goal |
| 点击顶部品牌／首页入口 | 进入 Library 根层；不清除阅读中的 Goal、书籍或位置；已在根层时保持稳定 |
| 首页进入 Goal、返回上级、搜索／筛选、查看归档／最近删除 | 只改变首页浏览上下文，不改变阅读中的 Goal |
| 从活动 Goal 的书籍列表打开书 | 正文与笔记读取成功后，一起提交书籍、该 Goal 和阅读页；不得仅因打开书而新增关联 |
| 从 Library 根层打开书 | 成功后进入无 Goal 的阅读上下文；失败时不清除原有阅读 Goal |
| 从归档／最近删除查看来源书籍 | 允许打开仍有效的来源，按无 Goal 阅读；不激活只读 Goal，不修改其关系 |
| 在 Goal 内添加／导入书籍 | 保持现有行为：添加关联后留在该 Goal，用户另行点击才打开正文；关联失败保留重试记录 |
| 首页根层导入书籍 | 保持现有显式“导入后阅读”行为；导入／开书失败留在首页，并区分已入库与未能打开 |
| 点击“继续阅读” | 返回已加载正文，不重置位置，不采用首页当前浏览的另一个 Goal |
| 阅读中展开 Goal 全页 | 进入 Goal 全页，保留正文；返回恢复原阅读页；没有可返回正文时返回首页 |
| Goal 材料跳转原文 | 来源验证和开书成功后进入阅读页并定位；失效来源留在原页面并说明原因 |
| 阅读中的紧凑书库切书／显式打开示例书 | 使用同一开书与导航流程；普通切书保留阅读 Goal，不自动添加关联；示例仅在明确点击时打开 |
| 删除当前书籍 | 删除成功后清除该书的运行时阅读上下文，返回首页，隐藏“继续阅读”；不补装示例书、不自动改开其他书 |
| 删除其他书籍 | 保留当前阅读会话，刷新相关列表；不新增页面跳转 |
| 备份恢复成功 | 返回首页并刷新，提示实际恢复数量；由用户选书，不自动开首本书或示例书；当前书被替换时清除旧阅读上下文 |

归档／最近删除内的材料定位继续沿用现有来源访问规则；本批不扩大对只读 Goal 的编辑权限。首页未提交草稿保留现有恢复机制，导航不能把它隐式提交或丢弃。

## 结构调整

新增一个小型 `src/client/app/navigation.ts`，统一管理 `home | reader | goal` 三种业务页面和 Goal 全页的返回目标。启动的 loading／setup／error 是独立状态面板，不属于阅读页。

- 导航负责发起页面切换、协调离开前保存、接收成功结果及安排焦点。`AppShell` 应用顶层页面可见性和工具栏状态；Goal 控制器继续负责同一个 Goal 面板在侧栏／全页的展示。
- 首页继续拥有浏览 Goal、集合、筛选、草稿等状态；Reader／Session 继续拥有当前书与位置；Goal 控制器继续拥有阅读 Goal 和编辑状态。导航不复制这些业务数据。
- `home.active`、`goals.page` 如需保留兼容，改为导航状态的只读派生值；逐步替换各处独立赋值及 `homeHidden` 推导页面的逻辑。不得维持两套可写页面状态。
- `main.ts` 保留装配职责；品牌点击、首页开书、继续阅读、Goal 展开／返回、紧凑书库、材料跳转、删除与恢复回调统一接入导航约定。
- 开书继续由 `AppCoordinator` 加载与校验，返回明确的成功／失败／被新请求取代结果。页面与阅读 Goal 在成功提交点更新，调用方不能在请求前先修改 Goal。
- 复用现有开书与材料跳转请求序号，加入导航失效条件：开书途中返回首页后，旧请求不能把用户拉回正文，也不能覆盖书籍、Goal 或来源定位。覆盖同书重复点击与跨入口竞争。

### 保存、加载与焦点

1. 离开已有阅读／Goal 编辑前，复用现有结束编辑与确认写入方法；写入失败保留当前页面、输入和恢复缓冲，显示可重试原因。首页新建草稿继续保留，不因切页自动建 Goal。
2. 数据加载期间保留原页面与加载反馈；只有有效请求成功后才切换。关闭目录、书库、外观、导出、选文浮层和 Goal 菜单，避免浮层残留在其他页面。
3. 首页与 Goal 全页禁止阅读翻页／模式快捷键；输入框、编辑器和中文输入过程中继续尊重现有键盘规则。Escape 优先关闭当前临时面板，不新增全局“返回上一页”。
4. 成功切页后将焦点移到首页标题、正文容器或 Goal 标题；返回正文先重算布局并恢复锚点。隐藏页面不应保留焦点或触发阅读命令。
5. 初始加载与建库提示放入独立状态容器，避免隐藏阅读页时连同 `desktop.ts` 当前挂在 `book-paper` 内的建库按钮一起隐藏。浏览器启动失败也提供可见的重试；启动成功标记仅在首页可用后设置，失败后允许重试完整初始化。

| 5. 验收与同步文档 | 更新实际行为测试、受启动假设影响的桌面测试，以及 README、reading-guide、PRD、known-limitations 中对应条目 | 自动回归通过，真实 Electron 指针／键盘与启动截图验收通过，记录剩余边界 |

## 验收清单

| 场景 | 必须验证 |
| --- | --- |
| 启动矩阵 | 空库、有书无 Goal、有 Goal 无书、书与 Goal 都有；桌面建库后、重启后、浏览器刷新后均进入首页；无自动开书／示例写入，无先露出阅读页的首屏闪现 |
| 首页导航 | 根层／子 Goal／上级／归档／最近删除／品牌首页入口；单击与键盘触发结果一致；浏览不覆盖阅读 Goal；创建草稿不因切页丢失或自动提交 |
| 选书与关联 | 根层开书清除阅读 Goal、Goal 内开书设置对应 Goal，均以开书成功为前提；添加关系不打开正文，开书不自动加关系；只读集合权限保持有效 |
| 同会话往返 | 阅读到章节中间 → 回首页 → 浏览另一 Goal → 继续阅读；原书、位置与阅读 Goal 保持；Goal 全页返回同样成立；无当前书时不能进入空白正文 |
| 失败与竞争 | 书籍不存在、读取失败、笔记／Goal 保存失败、关联写入失败；连续点击不同书、同书重复点击、开书中返回首页、材料跳转与切书竞争；旧结果不得覆盖当前状态 |
| 删除与恢复 | 删除当前书／最后一本书后留在首页且无示例重生；删除其他书不切页；恢复成功显示真实数量并留在首页，失败不误报成功；旧正文被替换后不能继续 |
| 页面交互 | 首页不能翻隐藏正文或切换阅读模式；切页关闭浮层；焦点落在可见元素；回正文重排保留锚点；窄窗口与主题切换没有新增遮挡 |
| 数据保持 | 导航不改书籍正文、笔记位置、Goal 树及关联；保存与恢复缓冲、删除来源保留 Goal 的既有规则继续通过 |

自动测试复用 `tests/regression/test_goal_home.js`、`test_open_book_race.js`、Goal 跨书／保存恢复、书库 Popover 等脚本；必要时新增 `test_app_navigation.js`，验证实际模块事件、状态和失败结果，不以源码搜索代替行为测试。

真实桌面以 `tests/desktop/goal-home.cjs` 为主补充启动、往返、焦点和失败截图。`restart.cjs`、Goal 生命周期、打包与稳定性脚本中依赖“启动即有当前书”的部分改为先断言首页、再显式选书，保留原数据与保存断言。主流程验收用隔离 profile，不读取或修改日常书库。

实施后执行 `npm test` 和 `npm run test:desktop`；原生对话框能力及安装机制未改动时，不为本批重复安装／签名验收。需要复测打包脚本时另行构建候选包，本批不发布。

## 交付判定

用户能稳定地从首页选书、按需使用 Goal，并在首页、阅读与 Goal 全页之间往返；失败保留原状态，迟到请求不抢回页面，删除／恢复不擅自开书。上述行为和测试同步后，本批完成，再进入双页下线。
