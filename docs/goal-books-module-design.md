# Goal 添加书籍：最小模块设计

2026-10-26。基于现有全局 Goal、可调侧栏、独立 Goal 页面、SQLite JSON 与书库代码。已按用户确认实施为一个独立新首页；现有 Goal 页面和阅读侧栏不增加书单、不调整 UI/UX。验收证据见 [实现记录](goal-books-implementation.md)。

## 1. 固定四条规则

1. Goal 可以先存在而没有书籍。用户明确添加一本书，才建立 Goal—书籍关联；同一本书可以关联多个 Goal。
2. 创建、查看或改写子 Goal，不要求再次选书。阅读中继续保留当前书；材料归入沿用当前选中 Goal，仍由用户主动操作。
3. 父级书籍在选书时帮助复用，不复制成每个子 Goal 的书单。移动节点保留其直接书籍关联和材料来源，改变的只是以后选书时的父级候选。
4. 打开书籍、归入材料和添加书籍是不同动作。普通打开不偷偷增加关联，关联材料保留原文来源；不建立“使用过”“继承中”等新状态或阅读行为跟踪。

三种意图发展均可沿用：先有问题再选书；从当前阅读产生子问题后继续读；问题改变方向后为同一 Goal 再添加其他书。Goal 的文字与层级变化不触发书单改写。

## 2. 用户流程与展示

首次体验由独立 Library 首页承载。数据库成功读取且书籍和 Goal 都为空时，展示两个入口 `Create a goal` / `Import a book`。前者在新首页输入自由文字，创建后在当前层级显示新 Goal；后者直接进入原导入和阅读流程，不创建默认 Goal。取消创建或导入回到空状态。已有内容时直接显示书库，新库不自动插入示例书；明确打开示例时才保存示例。无需通用路由或“引导已完成”存储字段。

新首页按 Goal 逐层浏览书籍。根层级显示顶层 Goal 及全部书籍；进入 Goal 后显示直接子 Goal 和主动添加的书籍卡片。Home、上一级和祖先路径用于导航，＋在当前层级创建并留在原处。书本＋展开选书列表，可选已有书籍或导入新书；成功后直接显示书籍卡片，点击即可阅读，不再经过 `View goal`。左上角 AuraReader 标识外观保持原样，支持点击或键盘回到书库根层级；有当前书籍时显示带书名的继续阅读入口。

浏览或创建不改变当前阅读意图；从某 Goal 的书籍卡片开书才选中该 Goal，从根层级直接开书不沿用隐藏的旧 Goal。继续阅读保留原书、意图与位置。首页只负责选择和打开书籍，材料仍由原 Goal 界面显示。

没有直接关联书籍的子 Goal，不展示要求“补全书单”的提示，也不阻断返回当前阅读。已有材料继续显示明确来源，无须为了材料来源补造手动书籍关联。

选择器复用一个列表：当前阅读书籍、父／祖先 Goal 的书籍靠前，随后是其余书库内容；去重并标识当前 Goal 已添加的书。旧 Goal 的 origin／材料来源可以作为已有候选线索，但不转换成用户手动添加记录。父级候选按需要查询，不持久化、不实时展开在子 Goal 页面、不提供继承设置。

从首页的 Goal 书单打开书籍，保持这个 Goal 为当前意图，进入已有阅读和侧栏流程。进入阅读后创建子 Goal，当前书和位置沿用原流程，不弹出选书步骤。本阶段保留原有高亮、笔记归入入口及可见规则。

## 3. 只新增一种持久关系

```ts
interface GoalBookLink {
  goalId: string;
  bookId: string;
  generation: string;
}

interface GoalLibraryState {
  goals: Goal[];             // 现有意图树
  links: GoalSourceLink[];   // 现有高亮／笔记关系
  bookLinks: GoalBookLink[]; // 新增：读者明确选择的书
}
```

书籍仍保存一份，继续属于现有书库。`generation` 复用现有书籍代次校验，防止删除后同 ID 重建的书被旧命令关联。关系按 `(goalId, bookId)` 去重。

继续在 `goal_library` 同一份 JSON 中保存，复用 revision、幂等命令、串行队列和恢复缓冲；没有新增关系数据库、工作区实体、继承表或关系转换任务。升级时补齐旧数据缺失字段，保留原书籍／标注 JSON，并更新库版本保护，阻止旧应用继续按旧语义修改新库。

旧待写命令保持原 opId 和命令内容重放。协议对旧命令缺少 `bookLinks` 保留现有关系；新客户端显式传递完整数组。不能把旧命令缺字段解释为删除所有书籍关系。

## 4. 接入现有模块

| 位置 | 最小改动 |
| --- | --- |
| `domain/goal.ts` / `GoalController` | 新增关系类型与添加／移除操作，复用原 Goal 选中状态与保存队列 |
| 新 `GoalHome` | 独立 DOM、创建输入、书单及选择列表；候选按需计算，冻结发起的 goalId；取消／Escape 恢复到添加按钮 |
| `GoalUI` / `ShelfUI` | 保留原文件；首页读取同一书库和 Goal 状态，不向现有页面插入新界面 |
| `AppCoordinator` | 导入增加可选目标 Goal；普通导入保持自动开书，Goal 导入则保存、关联并返回 Goal。继续复用原 EPUB/TXT 解析与文件选择器 |
| Goal repository、DataStore、HTTP/IPC | 扩展同一个 Goal JSON 字段、来源校验及事务清理；不新增一套保存队列或接口体系 |
| 启动装配 | 初始化成功后判断首次空状态；Goal 读取失败不视为空库，且区分读取失败与有待保存内容，避免误挡普通阅读 |

操作顺序：

- 从书库添加：冻结发起的 goalId → 用户选书 → 核对 Goal／书籍代次 → 同一 Goal 命令写入关联 → 确认后更新列表。
- 从 Goal 导入：冻结 goalId → 原解析并保存到书库 → 关联到该 Goal → 回到 Goal 列表。导入取消无变更；关联失败时书籍仍安全留在书库，保留关联恢复操作并明确反馈。重试只补关联，不重复导入。
- 从 Goal 开书：结束并确认原编辑 → 保持／选择指定 Goal → 走原 `openBook` 和原文定位流程。晚到的导入／选择结果不得强行打开书籍覆盖用户后来的导航。

## 5. 生命周期与备份闭环

- `Remove from goal` 仅移除对应 `bookLink`，保留书库原书及 Goal 已归入的高亮／笔记。材料关系表达保留的阅读内容，可以独立于当前书单存在。
- 从书库删除书籍时，同一事务清理对应 `bookLinks` 和原有材料链接；Goal 与子 Goal 保留。删除一条笔记只清理原材料链接，不清理主动添加的书籍关系。
- 改写 Goal 文字不改书籍关联。后续移动仅修改 `parentId` 和位置；直接书籍关联不变，候选列表下次打开时根据新的父级计算。
- 每书备份扩展为 1.3 的可选 `goalGraph.bookLinks`，只携带指向本文件书籍的关系。Goal 仅添加书籍、没有 origin 或标注时，也必须纳入这本书的相关根树备份。
- 是否包含高亮／笔记不影响书籍关系导出。逐本恢复只处理本文件覆盖的书籍关系，保留其他书的关联；旧 1.0–1.2 备份缺字段不清空已有关系。恢复时按目标书籍代次重绑定。原导出入口和每书文件规则不变。

## 实施顺序与验收

1. 增加 `bookLinks` 及兼容、校验、删除和备份适配，验证多 Goal 共用一本书、重复添加、旧命令恢复和逐书备份恢复。
2. 接入独立首页的书单和选择列表，覆盖添加、取消、移除关联和开书；复用原导入、存储与阅读流程。
3. 接入首次双入口与带目标 Goal 的导入，验证先创建／先导入两条流程；子 Goal 在当前阅读中创建后不需重复选书。
4. 回归真实桌面：A/B 两书关联同一 Goal、同书关联两 Goal；长书名与窄窗；导入中切换 Goal／取消；书籍保存成功但关联失败及重试；删来源、重启和备份恢复。原笔记、高亮、导入导出及 Goal 编辑检查继续通过。

当前阶段完成创建与添加书籍模块，后续移动／删除功能遵循上述关系边界，不在本阶段提前实现拖拽、阅读历史跟踪、继承管理或其他资源组织系统。
