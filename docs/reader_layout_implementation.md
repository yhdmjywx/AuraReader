# AuraReader 阅读区域排版优化实现文档

> 版本说明：本文记录初版排版方案。当前 UI 已改为常驻的沉浸式页边笔记，旧侧栏比例及展开／收起规则不再用于主界面。现行双页保持每栏 560px、栏间距 72px，仅在可用宽度至少 1612px、能容纳双侧笔记时启用；空间不足时暂用单页及右侧笔记，扩大窗口后恢复双页。底部笔记与双栏单右侧笔记暂不采用，留待后续一起评估。单页正文通常为 560px，在不足 844px 的窄窗口内适当收窄以保留右侧笔记。笔记原文引用仅在编辑和导出等原有流程中使用，不在页边重复展示。

本次将阅读正文调整为无外框、水平居中的简洁版式，仅以约 **1613 × 928px 的浏览器内容窗口**作为验收环境。保留当前单页／双页与笔记展开／收起的控制逻辑，只调整正文样式及与宽度直接相关的分页尺寸计算。

**确定的尺寸规则：笔记收起时，双栏为 560 + 72 + 560 = 1192px；笔记展开时，沿用阅读区可用宽度计算，适当收窄两栏，栏间距保持 72px。** 单页采用最大 560px 的正文宽度，在当前阅读区内居中。

## 一 适用范围与代码基线

以 `master` 上的修改前快照 `7b377d3` 为实现基线。`feat/ui-improvements` 已合并，现有章节分栏和阅读锚点调整已纳入该快照。旧版“把两个章节并排作为双页”的问题描述不能代替当前代码状态。

本次交付限定为阅读区域排版优化，不增加媒体查询、响应式断点、设置项、控件或配置参数。已有的窗口事件、分栏拖动、宽度不足时的双页降级机制继续保留，不新增其他窗口尺寸的适配与验收。

顶部工具栏、导出入口、底部分页导航、目录、书籍备份恢复及笔记工作台不在样式改动范围内。连续滚动模式沿用当前正文宽度和滚动行为，不套用本次单页／双页的宽度规则。

## 二 当前实现与保留边界

当前存在两条正文渲染路径，不能用同一种 DOM 布局替换它们。

| 当前模块 | 当前职责 | 本次处理 |
| --- | --- | --- |
| `src/client/styles.css` | 阅读区、正文容器、旧式左右页的样式 | 移除容器装饰，设置正文宽度、居中及双栏间距 |
| `src/client/domain/chapterFlow.js` | 分栏尺寸、栏序号、翻页步长 | 在现有 `columnMetrics` 内统一双栏间距为 72px，保留步长公式 |
| `src/client/features/reader/chapterColumnView.js` | EPUB 章节内 CSS 分栏、翻页和句子锚点定位 | 保留流程；确保所有尺寸仍取自实际正文容器及同一份分栏计算 |
| `src/client/features/reader/paperRenderer.js` | 演示书及未采用章节流的书籍，用左右两个正文元素渲染 | 保留渲染与原有分页，只兼容新的正文外观 |
| `src/client/features/layout/layoutController.js` | 单页／双页、侧栏状态、分栏比例及已有降级规则 | 保持不变 |
| `src/client/features/reader/readerController.js` 与 `src/client/main.js` | 几何变化前记录阅读位置，变化后重排并恢复 | 保持不变 |

普通导入 EPUB 的章节流使用一个 `bookPaper` 元素，通过 CSS columns 将同一章节依次排入左栏、右栏及后续栏；此时 `bookPaperRight` 和书脊元素已隐藏。本次继续使用这条路径，不改回左右两个章节容器。

模式切换和侧栏变化继续经过现有流程：`beforeGeometryChange → rememberAnchor → 更新布局状态 → syncReaderLayout → refitChapter`。保留按左上方句子恢复阅读位置的逻辑；正文变窄后显示栏数允许变化，不要求维持原来的显示栏号。

## 三 四种状态的最终布局

所有“居中”均以**当前阅读面板**为参照。笔记展开时，正文不以整个窗口为中心，否则会挤占笔记面板。

| 阅读模式 | 笔记状态 | 正文尺寸 | 水平位置 |
| --- | --- | --- | --- |
| 单页 | 收起 | 单栏 560px | 在全宽阅读面板内居中 |
| 单页 | 展开 | 单栏 560px；仍受现有可用宽度约束 | 在左侧阅读面板内居中 |
| 双页 | 收起 | 每栏 560px，间距 72px，总宽 1192px | 在全宽阅读面板内居中 |
| 双页 | 展开 | 总宽不超过 1192px，也不超过阅读区可用宽度；间距 72px，两栏等宽 | 在左侧阅读面板内居中 |

双页、笔记收起时，1613px 窗口对应的左右外围留白约为 `(1613 − 1192) ÷ 2 = 210.5px`。**约 210px 的留白只适用于这一状态。** 单页的留白更大，笔记展开时的留白按阅读面板单独计算。

默认笔记展开比例为阅读区约 75%。保持现有阅读视口左右各 32px 的内边距后，可用正文宽度约 1146px，双栏每栏约 537px。该数值是默认比例下的估算，最终取实际 DOM 尺寸；不得为凑到 560px 而改变侧栏比例或减少笔记区宽度。

沿用已保存的侧栏比例。上表不覆盖用户已有比例，也不重置 `aura_reader_width`。现有逻辑若判定双页应临时降级为单页，继续展示有效单页状态。

## 四 CSS 实施要求

### 1 阅读背景与容器装饰

将阅读面板背景与现有 `--bg-paper` 统一；默认白纸主题下为白色。正文容器与正文元素使用透明背景，去掉外围边框、圆角和阴影，避免形成另一张独立的“纸卡片”。不全局修改 `--bg-app`，不影响工具栏、笔记区及现有纸张主题选项。

需同时处理 `.paper-container.chapter-flow`、`.paper-container.spread-active`、普通 `.book-paper` 以及左右页圆角规则，避免某一渲染路径重新出现外框。只移除正文外围装饰，保留高亮、引用块、笔记卡片、分页导航分隔线及侧栏召回把手的样式。

旧式双页的书脊装饰不再显示，也不占用横向宽度；原书脊元素可保留。其渲染函数会设置内联 `display`，因此隐藏样式必须能覆盖该声明。双栏之间只保留 72px 的空白。

### 2 正文宽度与居中

复用现有 `.layout-single`、`.layout-double` 和 `.sidebar-collapsed` 状态类。单页正文容器采用 `width: 100%`、`max-width: 560px`；双页采用 `width: 100%`、`max-width: 1192px`，均设置左右自动外边距。在现有阅读视口内限宽，不新增窗口宽度判断。

章节流的容器继续保持 `display: block`。它的双栏来自正文内部的 CSS columns，不能把容器改成左右两个 flex 子页。

旧式双页继续保留左右两个正文元素：总宽采用相同的上限，使用 72px 的 flex 间距、两页等分剩余宽度。正文元素左右内边距归零，确保 560px 指实际正文排版宽度，而不是包含内边距的外框宽度。单页旧式正文也遵守同一口径。仅调整水平内边距，保留各路径现有的上下内边距。

检查 CSS 声明顺序和选择器优先级，确保原有 780px／1400px 宽度及左右页装饰不会覆盖新规则。只约束单页／双页，避免改变连续滚动模式的宽度。

### 3 纵向位置与文字排版

保留 `.reader-viewport` 的上下 32px 内边距，以及章节分页正文现有的上 28px、下 32px 内边距。保持容器原有高度与溢出方式，不用固定正文高度替代实际可用高度，不让分页模式退回纵向滚动。

保留字体、字号、行高、首行缩进、标题与正文间距、段落间距和底部分页导航高度。移除 1px 边框导致的轻微几何差异可接受，不借此调整正文顶部位置。

## 五 分页尺寸的最小同步

`layoutChapterStrip` 当前通过 JavaScript 内联设置 `columnWidth` 和 `columnGap`。只在 CSS 中写 `column-gap: 72px` 不会可靠生效，必须同步现有 `columnMetrics` 的双栏间距计算。

保留函数签名及调用方式，在函数内部将双栏间距确定为 72px；单页间距仍为 0。读取限宽后的实际 `paper.clientWidth`，继续计算等宽栏，不使用窗口宽度或整个阅读面板宽度代替正文宽度。

设实际正文宽度为 `W`，双栏尺寸为：

```text
gap         = 72
colWidth    = floor((W - gap) / 2)
screenWidth = 2 × colWidth + gap
stride      = colWidth + gap
screenStep  = 2 × stride
```

笔记收起时，`W = 1192`，得到 `colWidth = 560`、`stride = 632`、`screenStep = 1264`。下一组双页的左栏起点之间还包含右栏之后的间距，因此**翻页步长是 1264px，不能用可见宽度 1192px 替代**。笔记展开后重新按实际宽度计算，沿用同一公式。

保留当前 `screenStep`、`screenStartForColumn`、`pagedFrame`、末屏判断及栏数显示逻辑。初次布局、翻页、目录跳转、标注跳转和锚点恢复必须使用一致的尺寸来源，不能只修改首次渲染时的列宽。

保留 `.flow-start`、`.flow-pad`、`.flow-tail` 等分栏辅助节点及样式：它们用于句子落在左栏、奇数末栏补齐和末屏对齐，不属于待删除的容器装饰。

不改变书籍源章节、`page` 的含义、标注位置数据或备份格式。显示栏数变化只反映重新排版；已有阅读位置恢复继续使用当前章节与句子锚点，不能把新的显示栏号写回源章节位置。

## 六 实施顺序

1. 保留当前工作区中的章节分页与锚点调整，记录修改前四种状态的画面和阅读位置，建立纵向排版对照。
2. 修改 `styles.css`，完成白色统一背景、容器装饰移除、单页／双页限宽及旧式正文兼容。
3. 修改现有 `columnMetrics` 的双栏间距，核对各处实际宽度读取与步长公式，保持布局控制器和锚点流程不变。
4. 在现有章节分页单元测试中补充 1192px 双栏、笔记展开后较窄双栏及单页尺寸断言，执行必要自动检查与下述人工验收。

预计业务代码变更集中于 `styles.css` 和 `domain/chapterFlow.js`。只有发现实际尺寸读取未跟随容器限宽时，才对 `chapterColumnView.js` 做必要修正。无需修改页面结构、布局控制器、主入口事件绑定、存储或导出模块。

## 七 验收要求

验收使用同一浏览器内容窗口约 1613 × 928px、浏览器缩放 100%、默认白纸主题。这里的尺寸指内容窗口，不含操作系统标题栏或浏览器边框。以实际导入的 EPUB 为主要样本，进入有多屏正文的章节，避免仅用演示书判断章节分页效果。

| 验收状态 | 视觉检查 | 功能检查 |
| --- | --- | --- |
| 单页、笔记收起 | 正文约 560px，在阅读区居中，无外框 | 连续前后翻页、顶部与底部边界正确 |
| 单页、笔记展开 | 正文约 560px，在左侧阅读区居中 | 展开／收起不改变原阅读句子，标注与笔记可交互 |
| 双页、笔记收起 | 总宽约 1192px、单栏约 560px、间距约 72px，左右外围留白约 210px | 左栏后接右栏，下一组双页无截断第三栏、重复或漏文 |
| 双页、笔记展开 | 总宽按可用宽度收窄，两栏等宽、间距约 72px，不遮挡笔记区 | 连续翻页及侧栏切换保持阅读位置，末屏正常 |

宽度与居中位置允许约 1–2px 的浏览器取整差异。各状态正文顶部位置与修改前基本一致，字体与垂直间距不变，正文底部不被导航覆盖。

在章节中间依次执行“单页 → 双页 → 展开笔记 → 收起笔记 → 单页”，检查原左上方句子按现有锚点逻辑恢复。随后检查目录／书内链接跳转、高亮与笔记点击、标注范围、刷新后阅读位置恢复，以及奇数末栏和跨章节前后导航。页码或栏数允许随宽度重新计算。

旧式渲染路径做基本兼容检查：单页与双页均无外围装饰，正文、标注和导航仍按其原有机制工作。不得在本次顺带迁移演示书、TXT 或其他格式的分页机制。

自动检查使用现有 `npm run test:all`。新增断言应覆盖 `columnMetrics(1192, 'double')` 得到 560px 栏宽和 72px 间距、1264px 翻页步长，以及较窄正文下的等宽分栏和末屏起点；不为纯外观规则添加逐条复述 CSS 的测试。人工验收仅覆盖上述固定窗口中的四种状态，不扩展窗口尺寸矩阵。

## 八 实施结果与验收记录

业务改动已落地于 `styles.css` 与 `domain/chapterFlow.js`，并补充现有章节分页单元测试。布局控制器、章节渲染流程、句子锚点、标注和存储模块沿用原实现。

在约 1613 × 928px 的内容窗口中，以《巴黎圣母院（果麦经典）》的“大堂”章节验证：单页在笔记展开和收起时均为 560px；双页收起笔记时为 1192px，每栏 560px；展开笔记时实测约 1146px，每栏约 537px，间距均为 72px。容器边框、圆角和阴影均为零，默认阅读背景为白色。正文容器顶部较原样式仅有移除边框产生的约 1px 差异。

章节中途切换四种状态后，分栏起点仍为同一句原文。收起笔记时连续翻页偏移为 1264、2528、3792px，返回上一屏为 2528px。展开笔记时验证了奇数末栏、进入下一章节并返回上一章节末屏。目录和书内注释链接跳转、右栏选文的高亮入口与笔记编辑入口正常；取消笔记编辑未写入测试笔记。旧式正文路径的四种状态、连续滚动模式和原有纸张主题也完成兼容检查。

语法检查、单元测试和 15 项回归测试均通过。回归运行器在沙箱中启动子进程受到权限拦截，改在授权环境执行后通过。

**现有验收差异：跨刷新恢复阅读位置不具备当前实现基础。** `main.js` 的 `startApp` 固定打开示例书 `crisis-era`，`AppCoordinator.openBook` 固定从第 1 页渲染；浏览器刷新验证也呈现这一行为。本次没有改变这些启动和存储逻辑，因此“刷新后恢复上次书籍及位置”不计为通过。布局切换过程中的句子位置保持已通过，跨刷新恢复需另行定义和实施。
