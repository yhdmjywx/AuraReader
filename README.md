# AuraReader Workstation

AuraReader 是一个面向 PC 的本地 EPUB 阅读与笔记工作台，通过 Node.js 在本机启动服务，并在浏览器中使用。

相比平板，PC 拥有更自由和强大的软硬件生态、更便捷的键盘与鼠标操作，以及更充裕的显示空间。大尺寸显示器能够同时容纳更多阅读内容、功能界面及其他软件，减少屏幕空间对阅读和工作的限制。

AuraReader 正是基于这些优势而开发，致力于提供舒适的阅读排版、简洁高效的功能交互、便捷且沉浸式的高亮与笔记体验，并支持将书籍、高亮和笔记整合导出，让阅读成果能够在其他软件和平台中继续使用。

## Why AuraReader?

**The work of reading goes beyond reading itself.**

你知道的，市面上有很多阅读器。当你想要打开一本电子书——EPUB——开始阅读时，你读了，*You read… and… it’s over.* 这就完了。

当你开始在这本 EPUB 上写笔记时，你会发现，并不是每个阅读器都能在侧边实时展示你所做的笔记，并很好地将它们关联到原文。当你想要导出时，他们“慷慨”地给你提供了各种选择：导出图书、导出笔记、导出高亮。但你究竟需要的是什么呢？居然没有导出一个（图书+笔记+高亮）的方式。这很奇怪。你阅读的产物在导出时不应该被强行分裂。

问题还不止于此。你想把阅读工作的产物（书籍内容+高亮+笔记）带到其他平台和软件中继续使用，或者直接喂给 AI，却发现，导出成一种方便阅读、编辑和迁移的格式，也并没有那么容易。没错，我所说的就是 **Markdown**。

还有，许多阅读器总是在做大而全的功能库。当你使用它们时，有一个功能，明明是你想要的，却因为功能太多，你从来没有发现过它。有一个功能，明明你想快速找到它，却发现自己需要翻找各种各样的设置。你需要一个最简单、最便捷的阅读器。

**So, you need AuraReader. It’s for the work of reading, not just letting your eyes pass over the words.**

## 功能

- **沉浸式页边笔记**：在正文中选择文字即可添加高亮或笔记。高亮保留在正文中，笔记直接显示在对应原文外侧，不需要展开侧栏。笔记区只显示你的笔记内容，原文引用仍保留在编辑和导出中；点击笔记可以定位原文，也可直接编辑、删除。
- **跟随当前屏幕**：默认只显示与当前可见正文相交的笔记，双页包含左右两页。跨页引用只要仍有一部分原文可见，就保留该笔记；翻页、滚动或调整排版后自动更新。不再新建无原文引用的独立随笔，已有数据仍保留在存储和备份中。
- **两种主要导出方式**：
  - 想保留书籍内容并在 AuraReader 中备份、恢复，选择 **“导出书籍备份”（`.aurabackup`）**。每本书生成一个备份文件，包含书籍正文、目录以及高亮和笔记。
  - 想保存为 Markdown、放入知识库或直接提供给 AI，选择 **“分章节正文与笔记”（`.zip`）**。压缩包按章节保存 Markdown：高亮在正文中使用 `<mark>原文</mark>` 标记，跨段高亮分段闭合；笔记附原文引用与笔记内容，并放在对应原文段落之后。

  下图左侧展示了书籍在 AuraReader 中的单页阅读与页边笔记效果，右侧展示了同一章节导出 Markdown 后在 VS Code 中的预览效果，也可在 Obsidian 等支持 Markdown 的编辑器中使用。若希望保留为可在 AuraReader 中恢复的电子书备份，选择 `.aurabackup`；若只想导出笔记摘要，也可以单独选择 **“笔记摘要”（`.md`）**。页边笔记的筛选不影响全书导出与备份。

  ![左侧为 AuraReader 单页阅读与页边笔记，右侧为分章节 Markdown 在 VS Code 中的预览](src/client/assets/screenshots/markdown-export.png)

- **阅读与导航**：导入 EPUB、TXT，使用书库和目录打开书籍、跳转章节；支持单页、双页及连续滚动阅读，笔记直接显示在正文旁。
- **简洁排版**：正文与页边笔记共享阅读背景，没有侧栏分界线、卡片边框或展开操作。双页每栏保持 560px、栏间距 72px；笔记按窗口空间排列在两侧、右侧或底部，不挤压双页行宽。窗口不足以容纳完整双页时，自动暂用单页。
- **字体设置**：默认按书籍语言自动选择字体；内置更纱黑体和 Literata，正文精选字体随应用分发，离线可用。通过“更多字体”搜索本机字体，或导入 TTF、OTF、WOFF2。字体偏好对所有书籍生效。
- **其他阅读设置**：字号、首行缩进、阅读背景、单页／双页版式、界面明暗及全屏。
- **其他导出格式**：需要离线阅读时，可导出带标注的 HTML 电子书。

## 安装与启动

当前提供源码运行方式，已在 Windows 和 Node.js 24.16.0 上验证。要求 **Node.js >= 24.15.0**，使用内置 `node:sqlite`，并建议使用近期版本的 Chrome 或 Edge。本地服务只监听 `127.0.0.1`。

下载项目并解压，或克隆仓库，然后在项目根目录打开终端：

```powershell
npm ci
npm start
```

在浏览器中访问 [http://localhost:8095/](http://localhost:8095/)。使用期间保持终端和本地服务运行；在终端按 `Ctrl+C` 停止服务。

如果默认端口被占用，可以在 PowerShell 中指定其他端口：

```powershell
$env:PORT = '8096'
npm start
```

随后访问 `http://localhost:8096/`。SQLite 书库属于这份项目的 `data/` 目录，同一本地服务的不同浏览器或端口共用该书库；阅读偏好仍按浏览器访问地址保存。升级前的 IndexedDB 数据按原地址隔离，首次迁移应从原来的浏览器、配置文件和访问地址打开。

## 基本使用

1. 点击顶部书库图标，导入 EPUB 或 TXT，再打开书籍。
2. 点击书名旁的目录入口跳转章节，使用底部分页导航阅读。
3. 在正文中选择文字，添加划线或笔记；在页边笔记区查看、编辑及定位原文。
4. 点击顶部界面选项图标调整阅读设置。选择字体后立即应用；“更多字体”可读取本机字体、搜索或导入本地字体文件。
5. 点击顶部全屏按钮前的“导出与备份”图标，选择导出格式、导出书籍备份，或导入恢复备份。

| 快捷键 | 操作 |
| --- | --- |
| `D` | 切换单页／双页 |
| `←` / `→` | 上一页／下一页 |

输入文字或打开对话框时，阅读快捷键会受到互锁保护。

## 数据与备份

- 书籍解析结果、高亮和笔记由本地 Node.js 服务保存在 **`data/aurareader.sqlite`**。书籍和标注分别保存完整 JSON 对象，标注关联书籍；该目录不纳入 Git。应用不提供云同步或 AI 服务。
- 阅读偏好仍保存在浏览器 localStorage；保存失败时只保留尚未确认的操作作为短期恢复缓冲，成功后清理，不维持整书缓存或第二套主数据库。遇到保存冲突时，输入会保留在本机，请保留页面并处理冲突，勿清理站点数据。
- 用户导入的字体由本地服务保存到项目的 `data/fonts/`，该目录不纳入 Git。迁移应用目录时，如需保留这些字体，应一并复制该目录。
- `.aurabackup` **每个文件对应一本书**，保存解析后的正文、目录，以及可选择包含的高亮和笔记。批量选择多本书会分别生成文件。
- 书籍备份不包含全局阅读设置、自定义字体文件，也不是原始 EPUB 文件的逐字节副本。建议另行保留原始 EPUB。
- 更换设备或替换项目目录前，请导出书籍备份，或完成 SQLite 一致性备份并妥善保留整个 `data/` 目录。清理浏览器数据不会删除已确认写入 SQLite 的书库，但会删除阅读偏好和尚未写入成功的恢复缓冲。

### 从旧版本迁移

升级前先结束当前笔记编辑，关闭其他 AuraReader 标签页并停止旧服务，保留原项目和 `data/`。启动新版后，在**原浏览器、原配置文件、原访问地址**打开阅读器。首次启动会读取旧 `AuraReaderDB`，只使用只读事务，不会删除、清空或继续双写 IndexedDB。

迁移首先将原始数据库、相关缓存和待写操作分别归档到 `data/migration-snapshots/<来源哈希>/<快照哈希>/`，再合成有效数据：数据库记录优先，明确的待写保存／删除覆盖旧记录；普通旧缓存不能覆盖数据库。历史独立随笔、示例书关联、未知 JSON 字段、章节 HTML 和选区偏移均保留，不重新解析 EPUB。校验完整对象、内容哈希、关联和 SQLite 完整性后才切换；成功后只移除已归档的旧缓存及待写操作，旧 IndexedDB 原样保留。

若发现同 ID 不同内容、无法判断的仅缓存标注、损坏记录或无主标注，会停止该来源的切换，报告冲突并保存 `conflicts.json`。不得通过清空旧数据或删除迁移标识绕过冲突。迁移上传后中断可重新打开继续；同一份快照重复提交不会重复入库。不同浏览器的旧书库需要分别从各自原地址迁移，冲突不能静默合并。单次快照上传上限为 256MB，超过时会停止，不截断数据。

### 数据库校验与备份

```powershell
node src/server/storageMaintenance.js verify
node src/server/storageMaintenance.js backup
```

`backup` 使用 SQLite 在线备份接口，在 `data/backups/` 生成可独立打开并通过完整性校验的 `.sqlite` 文件，包含备份时已提交的数据。不要只复制正在运行的主文件而遗漏 WAL。

恢复备份前先停止服务，保留现有 `data/` 整体副本，在隔离目录验证备份后再替换数据库；不要覆盖运行中的库或遗留旧的 WAL/SHM 文件。`storage-installed.json` 用于识别已建立的书库；若数据库丢失／为空，服务会停止，避免悄悄新建空库。迁移原始快照用于重建迁移时的基线，之后的新修改应从 SQLite 备份或书籍备份恢复。不会自动回到旧 IndexedDB。

## 开发与测试

源码位于 `src/client/` 和 `src/server/`；前端采用渐进式 TypeScript 迁移，`npm start` 会先检查类型并构建到 `dist/client/`，再启动服务。依赖安装后，可以运行：

```powershell
npm test                 # 语法、单元和回归检查
npm run build            # 严格类型检查并生成浏览器使用的 JavaScript
npm run typecheck        # 只检查类型
npm run test:unit        # 单元测试
npm run test:regression  # 回归检查
npm run test:syntax      # JavaScript 语法检查
```

修改源码后重新运行 `npm run build` 并刷新浏览器；直接运行 `node src/server/server.js` 前也需先构建。迁移边界及运行方式见 [TypeScript 迁移说明](docs/typescript-migration.md)。

测试素材 `tests/fixtures/test.epub` 是 Project Gutenberg 的英文版《爱丽丝梦游仙境》，保留书内原始声明与许可。素材来源见 [测试素材说明](tests/fixtures/README.md)。嵌套目录另由自写测试样例验证。

## 当前限制与许可

- 当前支持 EPUB 和 TXT。虽然文件选择器包含 PDF 扩展名，但尚未实现 PDF 正文解析，不应将其视为支持的阅读格式。
- “原书字体”选项暂未启用；当前 EPUB 解析流程不会完整保留出版方的样式和字体规则，复杂排版与原书可能存在差异。
- 本机字体读取已在 Windows 本地服务下验证；其他环境取决于浏览器能力和授权，无法读取时仍可导入字体文件。
- 内置正文精选字体可由本地服务提供，但界面图标、界面字体和浏览器端 JSZip 仍引用外部 CDN。首次加载及部分功能依赖这些资源可用，当前不能保证完整离线启动。
- 页边笔记排版主要在桌面窗口验证；手机等小屏设备和复杂 EPUB 尚需进一步测试。
- 重新加载页面时，当前不会自动恢复上次打开的书籍和阅读位置；书库中的书籍和笔记仍可重新打开。
